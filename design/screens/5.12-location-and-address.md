## 2. Search (DES-304) — towns and places offline as you type, addresses on submit

ADR-0012 §5: Nominatim forbids autocomplete, so **addresses are searched only on an explicit action**.

| Input | Behaviour |
| --- | --- |
| Typing | offline `geo_search` typeahead: towns (Г) and places (М) of all of Russia, as today (no network) |
| Query looks like an address (contains a digit, «ул», «пр», «пер», «д.», «,») | under the field a helper line `addr_find_hint` `type.caption.md` `color.navi.hint`, and the first row of the list becomes the action row `addr_find_query` «Найти адрес «Советская 1»» (`search` icon 18 yellow, `type.list.title` `color.accent.yellow`, min-h 52); the IME action is «Найти» too |
| «Найти адрес» | one request (≤ 1/s): the action row shows `addr_searching` + a spinner (16, `motion.spinner`); then up to 5 address rows (badge У, name «ул. Советская, 1», sub `addr_sub` «адрес · Ярославль», km «≈ 3 км»), then the offline towns/places below |
| No address found | row `addr_none` `type.body.sm` `color.navi.labelSecondary` |
| Rate limited | toast `addr_rate` |
| Offline | the action row is replaced by the hint row `addr_offline` «Адреса ищутся только с интернетом — города и места доступны» (offline icon 16, `type.body.sm` `color.navi.labelSecondary`) |

## 5. S3-QA: keyboard and the Navigator header (Developer's question)

With the IME up the Navigator panel must not scroll its header or the focused field off screen (e2e 48, 72: «НАВИГАТОР · ВСЯ РОССИЯ / GPS ●» and the КУДА field were pushed out). Rule:

1. Window `adjustResize` + `imePadding()` on the screen root; the scene strip collapses (as built, dev-notes run 15).
2. The panel is a column with **fixed** parts and **one** scrolling part: header row (32: «НАВИГАТОР · …» + «GPS ●») → the **focused** field (64) → helper line (20, `addr_find_hint`) → result list (the only scrolling part, `weight(1f)`) → `addr_attribution` «© OpenStreetMap» (20, directly under the last row inside the list, so it scrolls with the rows).
3. While КУДА is focused, ОТКУДА collapses to one line under the header (h 28, `type.body.sm` `color.text.secondary`: «из Ярославля · вы здесь»; tap = focus ОТКУДА); while ОТКУДА is focused, КУДА collapses the same way. The «GPS ●» state stays in the header, so it is always visible.
4. Budget on the smallest window (360 × 640, IME ≈ 280 dp): status + back 40, header 32, collapsed line 28, field 64, helper 20 → ≈ 176 dp for rows = 2½ rows of 64, enough to see that the list scrolls. The «Найти адрес «…»» action row is the first list item, so it is always visible.
5. **IME up with no focused field** (S3-FINAL P1-01, e2e 48: the panel shrank to an empty 20 dp bar above the keyboard): this state must not exist. When a GPS fix sets ОТКУДА while the IME is up, hide the IME (`LocalSoftwareKeyboardController.hide()`) and clear focus together. If the IME is still visible without a focused field, lay the panel out as in the typing state (header + КУДА field); the panel's minimum height is header + one field (96).
6. Autofocus (R1 open question): after ОТКУДА is picked **by hand**, focus moves to КУДА and the IME stays up (the user is mid-entry). After a **GPS** fix sets ОТКУДА, nothing gets focus and the IME stays down.
