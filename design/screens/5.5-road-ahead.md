Mockup: `docs/design-canvas/Signs.dc.html` (390 × 1980, full scroll height) · Behaviour: SPEC 5.5, 13 · Components: §1.2, §2, §13, §14, §15, §16

## 1. Layout rules
- Root fill `color.dash.raised`. The strip (0–132), the back link, the overhead title sign and the new toolbar are **fixed** (not scrolled). Everything from y 150 down is a `LazyColumn` that scrolls under the dashboard cap (the cap at 110–150 is drawn above the list, so content slides under the dashboard edge).
- The Waybill button is **pinned** at bottom 24 (the mockup places it at the bottom of the 1980 page; on a phone it must stay visible, OI-26). A 24 dp fade (`color.dash.raised` alpha 0 → 1) sits directly above it. List bottom padding = 64 + 24 + 24 = 112 (+ the navigation-bar inset).
- The road column runs the full height of the list content. It is drawn per item (each item draws its own road segment at x 14–60), so it scrolls with the list. The lane-dash phase is global (`motion.lane.itinerary`), so the segments join seamlessly.

## 3. Copy rules
- Line 1: «старт» for the first stop, «через N км» afterwards (km from the previous stop); time «HH:mm» (stop local time).
- Service names: «Обед · <Town>», «Ночёвка · <Town>», «АЗС <where>», «Место отдыха».
- Cost: «вход свободный» (tickets 0), «≈ 1 800 ₽», «0 ₽» (rest).
- Tags (SPEC 5.5: с собакой, детское меню, парковка) are part of the note sentence, as in the mockup; no separate tag chips (OI-29).
- Unverified stops: line 1 gets « · не проверено»; the note starts «По открытым данным.» (SPEC 9).

## 9. S3-FINAL: open-data notice

With the real catalogue every trip carries `UNVERIFIED_PLACES`, so it must not look like a problem with this trip. Render it as the same info line as `route_approx` (5.12 §3): `info` 14 `color.text.muted` + `warning.UNVERIFIED_PLACES` «Места — из открытых данных: часы и цены уточняйте» `type.body.sm` `color.text.muted` + link «О данных». When both apply, one line: «Расстояния приблизительные · места из открытых данных · О данных» (`route_approx_open_data`). The yellow warning plates are only for warnings about this trip (`NO_LODGING`, budget, limits).

### 10.9 Online data — handled under the hood (CEO decision; replaces the Sprint 4 «states» draft)

There are **no visible data states**. The app shows whatever it has, automatically:

- **Parking** shows the zone tariff from the built-in data («P ≈ 300 ₽»), which works offline. No live free spaces, no live dot, no «свободно сейчас» / «было ≈ …». A stop with no tariff data shows «P ?» and the Waybill counts it «без данных» (§10.6).
- **No freshness labels** («обновлено N мин назад») and **no offline banner** on Road ahead.
- **Loading shimmer** only when a value is fetched for the first time and the fetch takes longer than 300 ms (`motion.shimmerDelay`); below 300 ms the value just appears. A value that is already known (built-in, cached) never shows a shimmer while it refreshes.
- **Offline, an online-only value missing:** a single quiet inline text `online_later` «уточним при интернете» (`text.muted`, the size of the text it replaces) in that spot, and nothing else — no icon, no banner, no dialog. Examples: the full Wikipedia summary on a card (the short offline text stays), address results (5.12 keeps its Sprint 3 hint).
- **Never an error screen** for anything that comes from the internet.
- Photos offline (5.9) and address search offline (5.12) keep their Sprint 3 behaviour.

The `S4-Offline.dc.html` canvas from the draft is removed: its tabs were demo switches, not UI.
