# 5.7 Exit to overnight («Съезд к ночёвке»)

Mockup: `docs/design-canvas/Exit.dc.html` · Behaviour: SPEC 5.7, 10, 14 · Components: §8, §9, §10, §12, §14, §15, §16

## 1. Layout rules
- Root fill `color.dash.base`. Night scene 0–430 top-anchored; dashboard top 410 (height 434) bottom-anchored. The navi panel stretches between top 54 and bottom 98 of the dashboard; the hotel list scrolls inside it when there are 3 options or the font is scaled.
- Short windows: the scene shrinks first (**min 260 dp** of scene, k = (dashTop + 20) / 430; was 300 — at a 640 dp window only one hotel fitted, final review F-04); below that the panel scrolls. Whenever the panel content overflows, a 16 dp fade (`color.navi.screen` alpha 0 → 1) sits at the panel's inner bottom edge and the next hotel option must peek by ≥ 20 dp, so the CEO sees that there is a choice.

## 8. Data mapping and the mock build (slice-2 review, for DEV-126)

| Slot | Source (engine trip JSON, `docs/contracts/plan-response.example.json`) |
| --- | --- |
| Entry | Road ahead «Выбрать отель →» on the overnight row of day k → Exit for that stop; `k` = index of the overnight among the trip's overnights, `n` = their count |
| Header right | `stop.kmAt` («КМ 263») · `stop.arriveAt` as HH:mm in `stop.tz` |
| Town | `stop.name` (the overnight town) |
| Reason | `reasons.overnights[day = stop.day].text` (engine `reasons.ru.json`); never composed in Kotlin |
| Options | `stop.hotelOptions[]` in engine order (max 3); selected = `stop.selectedHotelId`; name `name`; tags `tags` → `exit_tag_*` joined by « · », prefixed «не проверено · » when `verified = false`; price `priceCrewRub` → `common_estimate_rub` |
