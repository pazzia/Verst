## 1. Icon set

### 1.1 File format

| Property | Value |
| --- | --- |
| Canvas | `viewBox="0 0 24 24"`, `width="24" height="24"` |
| Content | exactly one `<path>`; no `stroke`, no `<image>`, no `<text>`, no transforms |
| Fill | `#141416` (`color.sign.black`); the colour is replaced by a tint at use, so one file serves every colour |
| Fill rule | `nonzero` (SVG and Android VectorDrawable default). Overlapping parts share one winding, so they union; ring holes (hotel head, view sun) wind the other way |
| Origin | Each icon is the stroke outline of the approved canvas centre-line at the approved stroke width (arrows 3, service 2.2, tourist 2 = `stroke.icon.sign`, `stroke.icon.pictogram`, `stroke.icon.thin`), with round caps and joins, converted to exact filled geometry: segments become rectangles, arcs become annular sectors (true SVG arcs), and vertices become discs. Cubic curves (the food knife blade) are flattened into 16 segments |
| Verification | Rendered at 240 px against the stroked source: arrows 0 px mismatch, pictograms ≤ 0.21 % of covered pixels (edge anti-aliasing only) |

Because the stroke is baked in, **draw these icons at exactly 24 dp × (target / 24) scale with no extra stroke**. An icon drawn at 28 dp has an effective stroke of 2.2 × 28 / 24 = 2.57 dp, the same as the canvas `<svg width="28" viewBox="0 0 24 24" stroke-width="2.2">`.

## 2. RoadSign variants — geometry for Compose

All sizes in dp at 100 % (signs do **not** scale with font scale; only their text does, inside the city sign). Draw order inside a sign: shadow (if any) → outer plate → inner border → white plate (service) → pictogram / text.

Border convention: "inner border" = a stroke whose **outer edge** sits `inset` dp inside the plate edge. In Compose draw it as `drawRoundRect(style = Stroke(width))` with `topLeft = inset + width / 2` and `cornerRadius = innerRadius − width / 2` measured to the stroke centre, so the outer edge of the stroke has exactly the listed radius.

### 2.6 Shared drawing helper

```kotlin
/** Draws a GOST plate: fill, optional inner border (outer edge `inset` from the plate edge). */
fun DrawScope.signPlate(
    fill: Color, radius: Dp,
    border: Color? = null, borderWidth: Dp = 0.dp, inset: Dp = 0.dp, borderRadius: Dp = 0.dp,
) {
    drawRoundRect(fill, cornerRadius = CornerRadius(radius.toPx()))
    if (border != null) {
        val w = borderWidth.toPx(); val i = inset.toPx() + w / 2
        drawRoundRect(
            color = border,
            topLeft = Offset(i, i),
            size = Size(size.width - 2 * i, size.height - 2 * i),
            cornerRadius = CornerRadius((borderRadius.toPx() - w / 2).coerceAtLeast(0f)),
            style = Stroke(w),
        )
    }
}
```
Usage: tourist = `signPlate(color.sign.brown, radius.r5, color.sign.white, stroke.w2, inset = 3.dp, borderRadius = radius.r3)`; city = outline first (`drawRoundRect` white with radius 6 over the 68 box), then the plate inset 2 with radius 4, then `signPlate(border = color.sign.black, borderWidth = stroke.w3, inset = 0.dp, borderRadius = radius.r4)`.

## 3. Importing the icons into Compose

1. Copy `design/icons/*.svg` into `android/core-ui/src/main/res/drawable/` as VectorDrawables (Android Studio "Vector Asset → Local file", or `vd-tool` in CI). Resource names use underscores: `ic_arrow_up_right`, `ic_service_fuel`, `ic_tourist_museum`, `ic_crew_dog`.
2. Draw with `painterResource(R.drawable.ic_service_fuel)` and `ColorFilter.tint(DesignTokens.color.sign.black)`, or an `Icon`-free `Image(..., colorFilter = …)`. No Material `Icon`.
3. Because the files contain one nonzero-filled path, the VectorDrawable keeps `android:fillType="nonZero"` (default). Do not convert to `evenOdd` — overlapping parts would cancel.
4. Content descriptions: icons are always decorative (`contentDescription = null`); the parent row speaks (components §2.5).

**Note on CTA and back-link arrows:** the canvases draw those with thinner strokes (2.6 and 2.5 in the 24 grid) than the sign arrows (3). Since the SVGs bake in stroke 3, using them at 22 / 14 dp makes those two arrows 0.37 / 0.29 dp heavier. That is below one physical pixel at 3× density and inside the QA tolerance; it is recorded here so QA does not flag it. If an exact match is wanted later, add `arrow-*-thin` variants (stroke 2.5) to `gen_icons.py`.

## 5. TalkBack

All pictograms and arrows are decorative. Meaning is carried by the row or button label (components §1.1, §2.5, §12). The arrow direction is spoken as part of the sign row: «на северо-восток» etc.
