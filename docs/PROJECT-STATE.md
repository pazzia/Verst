## 0. Коротко (TL;DR)

**Продукт.** «Верста» — Android-приложение для автомобильных поездок по России, с 29.10 также в 9 соседних стран.
- Пользователь задаёт «откуда — куда», экипаж, километры в день, бюджет и настроение («Как едем»). Можно взять
  и готовый маршрут рядом со стартом.
- Движок строит многодневный план: ночёвки, заправки, обеды, отдых, достопримечательности.
- Стоимость прозрачная, с формулами: «путевой лист».
- Отдельный режим «По городу пешком» строит прогулку.
- Ведение по маршруту не своё: приложение передаёт точки в Яндекс Карты / Навигатор или Google Карты.

**Движок** — пакет `verst_planner`: чистый Python 3.12, только стандартная библиотека.
- Один и тот же код работает на телефоне (встроен в APK через Chaquopy) и на сервере (FastAPI).
- Данные — открытые: Wikidata, OpenStreetMap, Wikipedia/Wikivoyage, Wikimedia Commons. Каталог собирается в
  GitHub Actions и лежит сжатым в пакете.
- **Отели, придорожные кафе и АЗС на трассе в демо-сборке вымышленные.** Достопримечательности, бары, кафе и
  рестораны в городах (для прогулок) и парки — настоящие, из открытых данных.

**Где сейчас проект.**
- Закрытое тестирование у CEO на его телефоне.
- Тестовый сервер в Нидерландах (только для тестов).
- Вся работа после 27.10 лежит в рабочей ветке `ccr-013d3489-181fz2` и ещё **не слита в `main`**. Сливать можно
  только по слову CEO «Сливай».
- Последняя сборка — **Верста 0.3.180** (артефакт CI `Verst-0.3.180`).

## 1. Продукт

### 1.1 Проблема и обещание (docs/SPEC.md)

- **Проблема.** AI-планировщики выдумывают маршруты. Картографические приложения ведут по дороге, но не
  планируют многодневную поездку. Конкурент Trippi не прошёл тест CEO.
- **Основная аудитория** — семейный водитель: 2 взрослых, 1–2 ребёнка, часто собака, поездки на 1–4 дня из
  большого города (сначала Москва). Также пары на выходные и дальнобойные поездки.
- **Обещание.**
  - Многодневный маршрут меньше чем за 10 с (p95), без регистрации.
  - Ночёвки по суточному пробегу со сдвигом к лучшему городу рядом.
  - Прозрачная стоимость: топливо, платные дороги, жильё, еда, билеты, парковки и резерв 10 %.
  - Сохранённая поездка работает офлайн.
- **Не цели MVP:** iOS; своя пошаговая навигация; аккаунты и синхронизация; платежи в приложении; живые цены
  отелей; общественный транспорт; электромобили; пуш-уведомления.
  - «Поездки за границу» тоже были не целью. CEO отменил это 29.10: волна 1, только через сервер.
- **Монетизация.** Только партнёрские ссылки (Яндекс Путешествия, Tripster через Travelpayouts, маркер
  `verst_app`). Pro — пока лист ожидания. Распространение — RuStore, Android 8+.
- **Бизнес-цифры.** Все в `docs/investor`, `docs/traction` — это **допущения**: 0 измеренных значений,
  0 проведённых интервью. План готовности к инвестору: `docs/backlog-investor-readiness.md`, вехи M1–M6.

### 1.2 Что умеет приложение сейчас (с точки зрения пользователя)

1. **Готовые маршруты рядом со стартом** («Золотое кольцо» и другие) или **любой пункт назначения**: поиск по
   офлайн-каталогу плюс поиск адреса по всему миру через Nominatim.
2. **Экипаж и настройки поездки.**
   - Взрослые, дети, собака; до 8 человек с водителем.
   - Километров в день: 150–900, шаг 50.
   - Бюджет.
   - Настроение «Как едем»: «Спокойно» / «Весело и познавательно» / «Только доехать».
   - Машина (расход, топливо, бак, «избегать платных дорог») задаётся в «Настройках».
3. **План поездки («Дорога впереди»)** — по дням, со «знаками» остановок.
   - Каждую остановку можно заменить на одну из 3 альтернатив, открыть её карточку (фото, описание, адрес,
     часы) или сообщить об ошибке.
   - У ночёвки — «Выбрать отель».
4. **Путевой лист** — стоимость по статьям с формулами, резерв 10 %, подгонка под бюджет.
5. **«Вести по картам»** — передача точек дня в Яндекс Карты / Навигатор или Google Карты. Приложение выбирает
   сервис по стране; пользователь может выбрать сам.
6. **«По городу пешком»** — прогулки по пресетам или «Свой маршрут» по интересам. Есть пресеты 18+ (рюмочные,
   пивные) с вопросом о возрасте и прогулка с собакой. Результат тоже передаётся в карты.
7. **Мои поездки** — сохранение до 50 поездок на телефоне или в выбранной папке. Есть «Поделиться».
8. **Поездки за границу** (BY, KZ, GE, AB, AM, AZ, UZ, KG, TR) — только сервер.
   - Знак «граница» и шторка с документами и сборами (всё помечено «не проверено»).
   - Расходы за границей посчитаны не полностью; итог это прямо говорит.
9. **Настройки** — машина, навигация, язык, валюта, тема, хранение, сервер («На телефоне» / «На сервере» с
   согласием), сведения о сборке.

### 2.2 Обязательные правила (установлены CEO; нарушать нельзя)

**Данные**
1. **Никогда не выдумывать данные.** Неизвестное показывается как «неизвестно» или «нет данных», а не как
   значение по умолчанию (ADR-0019 «unknown is not a default»).
   - CEO резко реагировал на «мест мало», когда данных просто не было: «Перестань меня обманывать».
   - Поэтому есть честное «нет данных» (`noData`) и «цена не указана».
2. **Платные сервисы данных не подключаем** («Пока в платные сервисы не идём»).

**Бренды и ключи**
3. **Реальные названия брендов** («Яндекс», «Google Карты») допустимы **только в строках `handoff_*`** (и
   `handoff_settings_*`). Это проверяют `BrandDenyListTest` и скриншот-тесты.
4. **Закрытый ключ подписи Яндекса в APK не встраивается.** Ключа для Навигатора пока нет (D-IR-17), CEO
   делать его не будет.

**Сервер**
5. **152-ФЗ.** Сервер в Нидерландах — только для тестов. Перед бетой с внешними пользователями нужен сервер в
   России (`docs/research/servers-ru.md`).
6. **Команды на сервере CEO выполняет сам.** Ассистент только даёт команды, **по одной строке, каждую в
   отдельном блоке кода** (чтобы копировать одним нажатием). Пошагово, без пачек.

**Git и сборки**
7. **Ветка.** Работа только в `ccr-013d3489-181fz2`; пушить в другие ветки нельзя.
8. **Слияние в `main`** — только после слова CEO **«Сливай»**. Pull request создавать только по прямой просьбе.
9. **Подпись APK.** Ключ лежит в GitHub Secrets: `VERST_SIGNING_KEYSTORE_B64`, `VERST_SIGNING_STORE_PASSWORD`,
   `VERST_SIGNING_KEY_PASSWORD`, `VERST_SIGNING_KEY_ALIAS=verst-demo`.
   - SHA-256 сертификата `24:30:6E:AC:…:D2:08`, CN=Verst Demo.
   - CEO решил оставить ключ в Secrets.
10. **Названия сборок осмысленные:** «Верста 0.3.N», файл `Verst-0.3.N.apk`.

**Работа ассистента**
11. **Субагенты не меняют состояние git.** Коммитит основной агент.

### 2.3 Как ассистент работает с проектом

**Ограничения песочницы.** Песочница **не видит** OSM, Nominatim, Geofabrik, Wikidata, cbr.ru, yandex.ru и

- данные собираются только в GitHub Actions (см. §14);

  артефакт `Verst-0.3.N`.

**Локальные проверки**
- `make check` — движок: ruff (длина строки 110), `mypy --strict`, unittest.
- `cd backend/api && python3 -m pytest -q` — API.
- `python3 design/tools/gen_strings.py --check` — строки приложения.

**Ссылки на сборки**

- Тестовые сборки рабочей ветки скачиваются как артефакт CI (нужен вход в GitHub):
  `https://github.com/pazzia/Verst/actions/runs/<run>/artifacts/<id>`.

```
                 │ PostgreSQL 16 (устройства, сохранённые поездки, отзывы, лимиты)           │
                 │ GraphHopper (опционально, профиль `routing`; на тестовой ВМ выключен)     │
                 └───────────────────────────────────────────────────────────────────────────┘
                                                     ▲
                 ┌──────────── Данные (GitHub Actions) ─────────────────────────────────────┐
                 │ Wikidata SPARQL, ru Wikipedia/Wikivoyage, Commons, Geofabrik+osmium      │
                 │ → catalogue_*.json.gz (в пакет) и abroad/<cc>/ (на сервер); ветки bot/*  │
                 └───────────────────────────────────────────────────────────────────────────┘
```

**Ключевые архитектурные идеи**

- **Один движок везде.** Модуль `mobile.py` — API в виде JSON-строк: строка на входе, конверт `{ok, result|error}`
  на выходе, никогда не бросает исключений. Его вызывает и телефон (Chaquopy), и сервер.
- **Порты и адаптеры.** Ядро зависит только от `typing.Protocol`-портов: маршрутизация, места, цены, платные
  дороги, регионы, часы, парковки, границы. Адаптеры:
  - `fake` — ручные миры;
  - `catalogue` — открытые данные;
  - `graphhopper` — реальные дороги, только на сервере.
- **Офлайн по умолчанию.**
  - Поездки по России строятся на телефоне без сети.
  - Сервер включается по желанию пользователя («На сервере»), после согласия.
  - Поездки за границу — только сервер.
- **«Неизвестно — не значение по умолчанию»** (ADR-0019). Часы, билеты, завтраки, виды топлива, рейтинги и теги
  несут состояние «неизвестно» через весь движок до интерфейса.
- **Генерация вместо ручной правки.**
  - Строки: `copy-ru.md` → `strings.xml`.
  - Токены: `tokens.json` → `DesignTokens.kt`.
  - Иконки, контракты API: `gen_api_contracts.py` → `docs/contracts/v2`.
  - Миры: `gen_worlds.py`.
  - CI проверяет, что сгенерированное совпадает с закоммиченным.

### 6.3 Модель данных (главное)

**Вход**

`TripInput`:
- `origin`, `destination` или `ready_route_id`, `vias` (≤ 3), `round_trip`;
- `crew` — взрослые 1–7, дети 0–5, собака, возраст детей; всего ≤ 8 человек;
- `daily_km` — 150–900, шаг 50; `budget_rub` — 1 000–10 000 000;
- `vehicle` — расход 4–20 л/100 км, `ai92|ai95|dt`, бак 20–150 л;
- `start_at`, `mood`, `avoid_tolls`, `reserve_on`.

**Справочные сущности**

- `Town` — с `population`, `quality` 0–3 и падежами.
- `Place` — sight, food, fuel, rest или lodging.
  - Часы: `None` = неизвестно.
  - Билеты, рейтинг: `None` = не оценено.
  - Теги: `tags` (подтверждено «да») и `tags_no` (подтверждено «нет»).
  - Источник: `source` curated / osm / partner.

**Маршрут**

`Route`:
- `points`, `cum_km`, `cum_min`;
- `details` — класс дороги, номер, платность;
- `waypoint_idx`;
- `synthetic` — оценочный маршрут. Отсюда флаг `approxDistances` в плане.

**Выход**

`TripPlan`:
- `days_list` — остановки `ScheduledStop` с id вида `d{день}s{nn}`, `kind`, временем, стоимостью, причиной
  `reason_ru`, альтернативами и `hotel_options`;
- `cost` — строки `CostLine` с формулами;
- `warnings`, `overnight_reasons`, `budget_fit`, `abroad`;
- **`engine_state`** — приватное. Позволяет заменить остановку без повторной маршрутизации.

**Перечисления**

- `StopKind`: start, sight, food, fuel, rest, overnight, via, finish, border.
- `Mood`: calm, more_stops (наследие v2), just_drive, fun.
- `WarningCode`: NO_LODGING, FUEL_GAP, DAY_OVER_BUDGET, TOLLS_UNAVOIDABLE, UNVERIFIED_PLACES, STOP_CLOSED,
  TIME_ZONE, ABROAD.

### 6.4 Конвейер планирования поездки

Порядок стадий: `Planner.plan → _plan_once`.

**Стадия 0. `normalize_input`**
- Проверка границ: «коробка России» (широта 41–82, долгота 19–180 и −180…−168). В `world_v1` вместо неё работает
  `BorderPort.check_point`.
- Проверка диапазонов из §6.3.
- Часовой пояс — по региону старта.
- Старт по умолчанию — ближайшая суббота, 08:00.
- Настроение по умолчанию: с детьми — `calm`, без детей — `more_stops`.

**Стадия 1. `resolve_points`**
- Точки: старт, промежуточные (или города шаблона готового маршрута), финиш; для кольцевой поездки — снова старт.
- Достопримечательности шаблона становятся фиксированными остановками.
- С границами (`world_v1`) вставляются точки пунктов пропуска.

**Стадия 2. `build_base_route`**
- Один вызов маршрутизации.
- Точка дальше 2 км от дороги → `UNREACHABLE`.
- Поездка короче 20 км (40 км для кольцевой) → `TOO_SHORT`.
- «Избегать платных», а платный участок всё равно есть → предупреждение `TOLLS_UNAVOIDABLE`.

**Стадия 3. `build_corridor`** — кандидаты вдоль маршрута.
- Радиусы коридора:

  | Что ищем | Радиус |
  |---|---|
  | Достопримечательности, еда, топливо, отдых | 15 км |
  | Топливо и отдых на магистрали | 5 км |
  | Города | 25 км (50 км для «якорных» городов) |
  | Жильё | 10 км от города |

- Каждый кандидат проецируется на маршрут (`km_at`, боковое смещение).
- Заезд: `2 × смещение × 1.3` км, по 40 км/ч, плюс 2 мин подъезда и 5 мин съезда с магистрали.
- Отсев по 10-километровым корзинам:
  - достопримечательности — 10 лучших, плюс 4 в пределах 30 мин заезда в мире открытых данных;
  - еда — 8 лучших.
- `admit_sights` убирает места в «домашней зоне» (30 км от старта), слабые места и места, куда нельзя с собакой.

**Стадия 4. `split_days`**
- Число дней: `N = ceil(всего / dailyKm)`, не больше 14.
- Ночёвки шаблона берутся, если укладываются в пробег.

**Стадия 5. `choose_overnights`** — выбор городов ночёвки.
- Цель дня `T`, окно поиска `[0.70; 1.05]·сегмент`, жёсткий потолок `1.05·dailyKm`.
- Цепочка запасных вариантов:
  - **F1** — лучший город с подходящим отелем;
  - **F2** — ближайший к цели в расширенном окне `[0.40; 1.30]` (плюс `NO_LODGING`);
  - **F3** — разбить поездку на N+1 дней;
  - **F4** — без отеля: город или точка у трассы, с подсказкой «ближайший отель в ≤ 60 км».
- **Формула оценки города:**
  ```
  S = 3·H + 2·Q + 1.5·E − 2·|km − T|/100 − detour/15
  ```
  - `H` — подходящие отели, не больше 5: с парковкой считается 1, без неё 0.5.
  - `Q` — качество города, `E` — вечерние достопримечательности. В настроении «Только доехать» оба равны 0.
  - «Якорные» города (≥ 200 000 жителей) получают +6.
  - При подгонке под бюджет добавляется штраф −0.5 за каждую 1 000 ₽ цены.
- Фильтры отеля:
  - у отеля есть цена;
  - с собакой нужен тег `dogs_allowed`;
  - с детьми и от 3 человек нужен `family_room`.
- Рейтинг отелей: рейтинг + 0.5 за охраняемую парковку + 0.3 за близость к центру − цена/10 000. Берутся 3
  лучших.

**Стадия 6. `build_day_plans`**
- Каркас каждого дня: START, фиксированные точки, OVERNIGHT или FINISH.
- Следующий день начинается в 09:00 по местному времени.
- Время в пути × 1.10.

**Стадия 7. Заполнение остановками** (порядок: топливо → обед → достопримечательности → обед после
достопримечательностей → визиты в город → отдых → расписание).

*Топливо*
- Запас хода — бак ÷ расход; заправка, когда остаётся 20 %.
- Поиск: на 40 км вперёд, иначе на 100 км назад.
- «Заправиться вечером», если порог наступает в пределах 60 км после ночёвки.
- Оценка АЗС: совпадение с другой остановкой, кафе, работа 24 ч, туалет, штраф за заезд.
- Нет АЗС → предупреждение `FUEL_GAP`.

*Обед*
- Окно 12:00–14:30. Заведение должно работать всё время обеда.
- Оценка: рейтинг + детское меню (если есть дети) + парковка + вид + штраф за заезд.
- Ужин и завтрак — только в стоимости, не остановки.

*Достопримечательности*
- Лимит на день: `calm` 2, `more_stops` 4, `fun` 5. В «Только доехать» не берутся совсем.
- В мире открытых данных:
  - пороги качества 0.40 (0.55, если заезд больше 10 км);
  - заезд до 45 мин для качества ≥ 0.70 (одна такая остановка в день), до 25 мин для ≥ 0.55;
  - нет транзитных остановок в 12 км от центра города-миллионника;
  - культовые места — не больше 30 % и не две подряд.
- В `fun` пороги мягче.

*Визиты в город ночёвки* (`town_visit`)
- Вечер: 0–3 места, если город достигнут до 16:00. Иначе одно место утром.
- Лимиты на вечер по настроению: calm 0, more_stops 2, fun 3.

*Отдых*
- Перерыв не реже чем раз в: calm 120 мин, more_stops и fun 90, just_drive 180.
- Порядок выбора: кофе на АЗС → площадка из пула → расширенный поиск → остановка у дороги на 15 мин.
- В `fun` на перерыв ставится интересное место: 30–45 мин, с пояснением, для кого оно (`fun_for`).

*Расписание и починка* (`schedule`)
- Длина дня: calm 540, more_stops 600, just_drive 720, fun 660 мин.
- Плохой день (перебор времени, закрытое место, обед вне окна):
  1. выбросить худшие достопримечательности;
  2. убрать автоматические остановки;
  3. перезапустить стадии один раз.
- `final_repair`: убрать закрытые места, перепланировать обед и отдых.

**Стадия 8. Альтернативы**
- До 3 на каждую заменяемую остановку из её пула. Условия: прибытие ±45 мин, день остаётся допустимым, хватает
  топлива; кандидаты ближе 2 км друг к другу склеиваются.
- Каждая альтернатива несёт готовый патч дня. Поэтому на телефоне замена делается без движка: Kotlin
  `TripEditor`/`CostCalculator`, затем ответ движка.

**Стадия 9. Стоимость** — §6.5.

**Стадия 10. Сборка ответа** (`_assemble`)
- Причины выбора ночёвок.
- Предупреждения `UNVERIFIED_PLACES` (есть места из OSM) и `TIME_ZONE`.
- `approx_distances = route.synthetic`.

**Стадия 11. Подгонка под бюджет** (`fit.py`, ADR-0011) — только если задан бюджет и он превышен.
- Лестница рычагов:
  1. дешёвое жильё (+ семейные номера);
  2. экономная еда (чеки × 0.75);
  3. бесплатные достопримечательности;
  4. меньше ночей (dailyKm + 50, до min(1.3×, 900));
  5. более короткий вариант готового маршрута.
- Допуск: `бюджет + min(5 %, 3 000 ₽)`.
- Исходы:
  - `fits`;
  - `small_overrun`;
  - **`no_fit`** — самый дешёвый план (`minimum`) и до 3 вариантов: сократить, дешевле маршрут, поднять бюджет.
    Не больше 8 дополнительных прогонов.

**Прочие входы**
- `replace_stop` — пересобрать один день из `engine_state`.
- `recompute_cost` — пересчитать стоимость: экипаж, бюджет, резерв, выбор отеля. Смена собаки или детей требует
  перепланирования (`replan_required`).
- `estimate_km` — только стадии 0–2.

**Прогресс.** События `stage` (`split` / `lodging` / `fuel` / `hours` / `cost` / `budget`, доля 0.05 → 0.92) и
`stop` (предварительные ночёвки). Отмена через `CancelToken` проверяется между стадиями.

**Часовые пояса**
- Время дня считается по часам места старта дня, поэтому не скачет на границе поясов.
- Остановки в другом поясе получают `local_tz` и `local_time_ru` («По местному времени — 12:22 (+1 ч)»).

### 6.5 Стоимость (`cost/*`, ADR-0009)

**Округление** — Decimal HALF_UP:
- строки — до 10 ₽;
- резерв — 10 % от суммы, до 10 ₽;
- итог — до 100 ₽;
- на человека — до 100 ₽.

**Статьи**

| Статья | Как считается |
|---|---|
| Топливо | Σ км по регионам × расход / 100 × цена в регионе |
| Платные дороги | По участкам. Ночной тариф, если въезд 00:00–06:00; выходной тариф пт–вс; оценочные участки помечены «(примерно)» |
| Жильё | Номера × цена. Номера: `ceil(взрослые/2)`, дети вместе со взрослыми, или семейные |
| Еда | Обед в дни, когда поездка накрывает обеденное окно. Ужин в городе ночёвки. **Завтрак 0.6 × чек**, если завтрак в отеле не подтверждён (ADR-0019 E-3). Дети до 7 лет считаются как 0.5 |
| Билеты | Неизвестные цены = 0 и перечисляются в `total_note_ru` |
| Парковки | Москва и СПб — тарифные зоны; иначе OSM `fee=yes` в 300 м; иначе бесплатно или неизвестно |
| Резерв | 10 % |

**Расхождение.** В SPEC §8 «завтрак включён» — заменено ADR-0019.

**Эталон пересчёта.** `cost/recompute.py`, закреплён контрактом `tests/contract/cost_recompute_cases.json` для
Kotlin-порта.

**Платные дороги в `russia_v1`**
- `RoadRateTolls` — по реальной геометрии. Тарифы `toll_rates.json` для М-11, М-12, А-113, М-4, М-3, М-1;
  `verified: false`, данные на 02.03.2026.
- `CorridorTolls` — для оценочных маршрутов. Участок, оба конца которого в 50 км от платного коридора, платит
  долю цены коридора.

### 6.6 Настроения «Как едем»

| Настроение | Подпись в UI | Что меняет |
|---|---|---|
| `calm` | «Спокойно» | 2 достопримечательности в день, отдых раз в 120 мин, день 540 мин, без вечерних визитов |
| `fun` | «Весело и познавательно» | 5 мест в день, мягкие пороги качества, интересные места на перерывах, вечер до 3 мест, день 660 мин |
| `just_drive` | «Только доехать» | Без достопримечательностей и визитов, отдых раз в 180 мин, день 720 мин |

`more_stops` (наследие v2) остаётся значением по умолчанию без детей. Отправляет ли его приложение сейчас —
(не проверено).

**Режим открытых данных.** В мирах с открытыми данными включены `anchors`, `diversity`, `town_visit` и
`honour_template` (`mobile.OPEN_DATA_CONFIG`). Ручные миры работают на значениях по умолчанию: от них зависят
эталоны G01–G13.

## 7. Маршрутизация

- **`FakeRouting`** — Дейкстра по ручному графу.
- **`HybridRouting`** — телефон и `russia_v1`:
  1. все точки в ~7 км от узлов графа → маршрут по графу;
  2. иначе граф плюс прямые подъезды по модели дороги;
  3. иначе полностью оценочный маршрут.
  - Точка дальше 60 км от любого города каталога → `UNREACHABLE`.
- **Модель дороги** (`geo/roadmodel.py`, `resources/detour_model.json`):
  - `км_дороги = прямая × коэффициент(прямая)`; время — по скорости.
  - Опорные точки (прямая км → коэффициент, скорость): 65.7 → 1.089 / 80 км/ч; 201.4 → 1.223 / 80.6;
    423.2 → 1.314 / 82.5; 708.5 → 1.388 / 87.7.
  - Калибровка `tools/calibrate_detour.py` на 818 парах городов: ошибка по км (MAPE) 17.1 %, p90 35.2 %.
  - Оценочный маршрут ⇒ в плане `approxDistances` («расстояния примерные»).
- **МКАД/ЦКАД** — `bypass_roads.json`: 6 узлов, 16 рёбер, только для `russia_v1`.
- **GraphHopper 11** (ADR-0017, `adapters/graphhopper/`):
  - Профили `car` и `car_avoid_tolls`. Ограничения прилипания: магистраль, тоннель, мост, паром. Таймаут 6 с.
  - Используется **только на сервере** (`ServerRouting`). Откат на модель дороги — только при
    `VERST_SYNTHETIC_FALLBACK=true`.
  - На тестовой ВМ выключен (`VERST_ROUTING=road_model`), граф не помещается в память. Решение D-IR-21 —
    режим MMAP (60.8 маршрута/с).
- **За границей** — `foreign/routing.py`:
  - **`BorderRouting`.** Российские отрезки идут через обычную маршрутизацию мира. Отрезки с концом за границей
    — по модели дороги. Части сшиваются; если хоть одна оценочная, весь маршрут оценочный.
  - **`TownChain`** (31.10). Участок за границей ≥ `VIA_MIN_LEG_KM` 400 км проводится через кратчайшую цепочку
    городов с населением ≥ `VIA_MIN_POP` 10 000.
    - Прыжок между городами ≤ `VIA_HOP_KM` 350 км; цепочка не длиннее `VIA_MAX_DETOUR` 1.5 × прямой.
    - Алгоритм — Дейкстра по полному графу кандидатов внутри эллипса.
    - Зачем: Москва → Алматы шла прямой по степи с 4 ночёвками «у трассы». Теперь идёт через Шалкар, Байконур,
      Кызылорду, Кентау, Жанатас.
  - **`BorderTolls`** считает платные дороги только на российских частях.

## 9. Прогулки «По городу пешком» (`city/*`, ADR-0013)

### 9.1 Пресеты (`city/presets.py`)

| Пресет | Веса | Порог «есть данные» | По умолчанию | Ограничения |
|---|---|---|---|---|
| `overview` «Обзорный» | Достопримечательности | ≥ 4 мест | 240 мин, обычный темп | Музеев ≤ 2, в музее ≤ 45 мин |
| `museums` «Музейный» | Музеи | ≥ 3 музеев | 360 мин, медленный темп | Музеев ≤ 5 |
| `dog_walk` | Только парк, природа, набережная, видовая точка, площадь | ≥ 2 | 120 мин | Показывается только с собакой |
| `ryumochnye` (18+) | Только рюмочные | ≥ 3 | 240 мин | Напитков ≤ 5 |
| `beer` (18+) | Крафт и пабы | ≥ 3 | 240 мин | Напитков ≤ 5 |
| `custom` «Свой маршрут» | Интересы: history, architecture, museums, parks, food, bars, views | — | — | Музеев 4, напитков 5, еды ≤ 3 и ≤ 1 на 2 ч |

**Длительность.** 120 / 240 / 360 / 480 мин или «без ограничения» (считается как 480 мин, радиус 6 км,
до 12 остановок).

**Темп.** Медленный 3.5 км/ч (стоянки × 1.25), обычный 4.5 (× 1.0), быстрый 5.5 (× 0.8). Коэффициент
извилистости 1.30. Переход между остановками ≤ 2.5 км. Радиус ≤ 3 / 4 / 5 / 6 км.

**Цены.** Рюмочная 300 ₽, паб и крафт 600, бар 500 (на взрослого). Обед в длинной прогулке — 600 ₽, это
**оценка**. У кафе из OSM цен нет: «цена не указана».

**Плейграунды** без детей получают вес 0.

### 9.2 Кандидаты и пул (`mobile._candidates`, `pool_mix`)

- **Источники.** Достопримечательности (`places_near`), бары, еда и **парки** из сеток каталога.
- **Пул ≤ `POOL_MAX` 60.**
  - Еда и бары занимают ≤ `POOL_PER_CAP` 3 × их лимит остановок; остальное — достопримечательности.
  - Если достопримечательностей мало, освободившиеся места снова отдаются еде и барам.
  - Зачем (31.10): в СПб со всеми интересами 56 из 60 мест были кафе → «мало мест» в центре. Теперь 10 остановок.
- **Популярность.**
  - Парк: по площади, 0.3–0.9 (логарифмическая шкала).
  - Бар: 0.5 + 0.2 за известные часы.
  - Кафе: 0.5 + часы + кухня.

### 9.3 Решатель (`city/walk.py`, задача ориентирования)

- **Оценка:** `100 × популярность × вес (+10 за объект наследия)`. Убывающая отдача по виду: k-й объект того же
  вида × 0.6^(k−1).
- **Построение.** Жадная вставка двумя способами (по Δоценка/Δминуты и по Δоценка); лучший побеждает. Затем
  улучшения до `MAX_MOVES` 200 ходов:
  - вставка пар из 25 лучших;
  - 2-opt;
  - одиночные замены;
  - «выбросить и долить».
- **Ограничения:**
  - бюджет времени;
  - часы работы на весь визит (ожидание ≤ 60 мин);
  - переход ≤ 2.5 км;
  - бюджет группы;
  - лимиты по видам.
- **Окна старта.** Днём 9–22, музеи 10–22, бары 18–23; иначе «завтра».
- **Возврат к старту** — по желанию («Вернуться к старту»).
- **Мало мест.** Меньше 2 остановок → `NOT_ENOUGH_POIS`:
  - до 3 **проверенных** подсказок, каждая реально решена: снять исключения, длиннее, без ограничения, другой
    пресет;
  - различие «нет данных» и «мало мест» (`reason: no_data | few_places`, `messageRu`).
- **`NO_CITY`** — рядом (15 км) нет города каталога.
- **`city_presets`** — доступность, число мест, `noData`, время старта и `adultOnly` для каждого пресета.

## 10. Передача в навигатор и карты (`handoff.py`, ADR-0014/0015)

**Машина**
- Один день: с выбранной остановки или со старта дня до конца дня.
- Берутся sight, food, via, overnight, finish (заправки и отдых навигатор ведёт сам).
- `MAX_VIAS = 8`, приоритет via/overnight/finish > sight > food. Если точки отброшены — `truncated`.
- Ссылки:
  - `maps` — `yandexmaps://…?rtext=…&rtt=auto`;
  - `navigator` — `yandexnavi://build_route_on_map?…`;
  - `navigatorNext` — только следующая точка;
  - `web` — `https://yandex.ru/maps/?rtext=…`.
- Порядок по умолчанию: Карты → Навигатор до следующей точки → браузер. Причина: неподписанные запуски
  Навигатора ограничены 5 в день.
- Подпись: `client=` и `toSign`. RSA-подпись должно ставить приложение; ключа нет.

**Прогулка**
- `rtt=pd`, **≤ 10 точек на часть** (`MAX_WALK_POINTS`). Длинная прогулка делится на части с общей точкой на
  стыке.
- С 31.10 приложение подписывает части: «Часть 1 из 2 · до …», последняя — «· обратно к старту».

**Google Карты.** Ссылки строит **Android** (`NaviLinks.googleRoute`, ≤ 8 промежуточных точек, разделитель
`%7C`).
- Выбор сервиса по стране (`MapsCountries`): Яндекс в RU, TR, AZ, AM, KZ, KG, TJ, BY, GE, UZ, MD; в остальных —
  Google.
- Пользователь может переопределить выбор в «Настройках».

**Коды ошибок**

| Код | Когда |
|---|---|

## 12. Сервер `backend/api/verst_api` (FastAPI, ADR-0020 «минимальный бэкенд для беты»)

**Стек.** fastapi, uvicorn (2 воркера), pydantic, psycopg (пул), prometheus-client. Redis, SQLAlchemy и Alembic
нет.

**Эндпоинты**

| Эндпоинт | Что делает |
|---|---|
| `POST /v1/devices` | Анонимное устройство (ADR-0007): токен Bearer 32 байта, хранится только sha256; 20 в час с IP |
| `DELETE /v1/devices/me` | Удаляет устройство и всё, что с ним связано |
| `POST /v1/trips/plan` | JSON или **SSE** (`Accept: text/event-stream`, ADR-0006). События `stage`, `stop`, `done`, `error`, пинг каждые 5 с; таймаут 25 с; отмена при разрыве; **ничего не сохраняется** |
| `POST /v1/route` | Только GraphHopper |
| `GET /v1/ready-routes` | Готовые маршруты рядом |
| `POST /v1/trips` | Сохранить поездку: обезличенная копия, ссылка `/s/{slug}`; до 50 на устройство |
| `DELETE /v1/trips/{id}` | Снять публикацию |
| `GET /v1/shared/{slug}`, `GET /s/{slug}` | Публичная поездка без экипажа, бюджета, дат и машины; HTML-страница с `noindex` |
| `POST /v1/feedback` | Телефоны и e-mail маскируются; текст живёт 180 дней |
| `GET /v1/links/hotel` | Поиск по городу в Яндекс Путешествиях |
| `GET /privacy` | Политика конфиденциальности |
| `/healthz`, `/readyz`, `/metrics` | Здоровье и метрики; `/readyz` и `/metrics` закрыты на прокси |

**Движок на сервере** (`engine.py`)
- Загружает `central_russia_v1` → `russia_v1` → `world_v1`.
- `Planner` с серверной маршрутизацией и `OPEN_DATA_CONFIG`, обёрнутый в `AbroadPlanner`.
- Один поток на процесс. Зависит от приватных функций моста (`_WORLDS`, `_trip_result`), они проверяются при
  старте.

**Ошибки → HTTP.** 400 `INVALID_INPUT`, 401, 404 `NOT_FOUND`/`UNREACHABLE`, 409 `LIMIT_REACHED`, 413, 422
`TOO_SHORT`, 429 (с `Retry-After`), 503 `UPSTREAM`, 500.

**База.** PostgreSQL 16, схема `api`: `device`, `trip`, `feedback`, `rate_counter`. Лимиты — счётчики с
фиксированным окном. Свои миграции под advisory lock.

**Приватность (R-07)**
- Координаты в базе и логах округлены до 2 знаков.
- Журнала доступа нет.
- IP хранится только как HMAC внутри ключей лимитов.

**Лимиты в час.** Планирование 30, маршрут 60, сохранение 20, отзывы 10 в день.

**Переменные окружения**
- `VERST_ROUTING` (`road_model` | `graphhopper`), `VERST_GRAPHHOPPER_URL`, `VERST_SYNTHETIC_FALLBACK`;
- `VERST_ABROAD_DIR`, `VERST_RATES_FILE`;
- `VERST_WORKERS`, `VERST_DATABASE_URL`, `VERST_PUBLIC_BASE_URL`, `VERST_RATE_KEY_SECRET`.

**Известные слабости** (ревью 28.10):
- один поток движка на процесс: до 5.7 с при 20 одновременных планах;
- лимиты обходятся регистрацией новых устройств.

### 13.2 Архитектура приложения

**`MainActivity`** — одна Activity.
- Язык приложения из настроек (по умолчанию русский).
- `VerstRoot`: экран по `flow.top` плюс оверлеи — тосты, жалоба, диалоги, согласие на заграницу, лимит хранения.

**`VerstApp`** создаёт:
- `EngineHost` — старт Python, загрузка миров, `load_catalogue`;
- `tripStore` (`MirroringTripStore` вокруг `FileTripStore`);
- `ServerClient`;
- `gateway = ServerPlannerGateway(ChaquopyPlannerGateway(engine), server)`;
- `VerstFlow`.

**`nav/VerstFlow.kt`** (около 1 900 строк) — **единое состояние приложения**: Compose snapshot state, без
ViewModel.
- Стек экранов `Route { Windshield, Navigator, Instruments, Drive, Road, Waybill, Exit, Debug, NoFit, City, Walk, Settings }`.
- `back()` сначала закрывает шторки.
- Логика разнесена по расширениям:
  - `CityFlow.kt` — прогулки, вопрос 18+, сборка и пересборка, подсказки, передача прогулки в карты;
  - `HandoffFlow.kt` — выбор карт, передача дня, шторка передачи, `abroadHandoff`;
  - `LocationFlow.kt` — GPS, поиск адреса;
  - `CardsFlow.kt` — карточки, адрес, жалоба;
  - `BudgetFlow.kt`, `ExitFlow.kt`.
- **Хранение.** Один последовательный писатель: `saved.json`, `last.json` (восстановление экрана и прокрутки
  после смерти процесса), `defaults.json`, очередь жалоб.

**Шлюзы движка**
- `ChaquopyPlannerGateway` — вызовы `verst_planner.mobile` в одном потоке; отмена через `mobile.cancel`.
- `ServerPlannerGateway`:
  - поездка по РФ идёт на сервер, если включено «На сервере», есть согласие и сеть; при любой проблеме — откат на
    телефон, причина видна в «Настройках»;
  - **поездка за границу — только сервер**, без отката: ошибки `ABROAD_NO_SERVER` / `ABROAD_NO_CONSENT` /
    `ABROAD_OFFLINE`.
- `ServerClient`:
  - регистрация устройства;
  - SSE `/v1/trips/plan`;
  - «Проверить соединение» (`/healthz`);
  - «Отвязать от сервера».

**Сеть.** Один клиент OkHttp. Повторы с джиттером, «предохранитель» на хост (3 сбоя за 60 с → хост
закрывается на 5 мин), дисковый кэш Coil 64 МБ.

**Данные**

`Nominatim.kt`:
- Поиск и обратный геокодинг, **по всему миру**.
- Ограничение 1 запрос/с, кэш на 24 ч.
- `viewbox` ±0.4° без жёсткой привязки — сначала местные улицы.
- Строка за границей показывает «город · Страна». Крым и Севастополь считаются Россией.
- Запасной вариант — геокодер телефона (`AndroidGeocoder`).

`FileTripStore`:
- Атомарные JSON-файлы, ≤ 50 поездок (предупреждение с 45).
- Битый файл переименовывается, не перезаписывается.
- По желанию — копия в папку через SAF.

**Платформа** (`Platform.kt`)
- `AndroidLocator` — `LocationManager` без Play Services, потому что RuStore. Свежий кэш < 2 мин, иначе гонка
  провайдеров, таймаут 20 с.
- `IntentHandoffLauncher` — Яндекс Навигатор / Яндекс Карты / Google Карты; браузер, если приложения нет.
- `TelephonyCountrySource` — страна по сети или SIM, иначе по локали.

**Аналитика.** AppMetrica только при ключе, через `PrivacyGuard`.

## 14. Данные: сборка каталогов

Всё собирается **только в GitHub Actions**: песочница не видит источников. Скрипты лежат в
`backend/planner/tools/data/`, это чистый Python; склонение городов — pymorphy3. HTTP аккуратный: один запрос за
раз, User-Agent `VerstDataBot/0.3`.

**Источники**
- Wikidata SPARQL: города, достопримечательности, классы, регионы, часовые пояса.
- ru Wikipedia: выдержки, фото страниц.
- ru Wikivoyage: дамп.
- Wikimedia Commons: авторы и лицензии, размеры, геопоиск фото.
- Geofabrik OSM + `osmium`: бары, еда, парки, POI, платные парковки.
- Курсы ЦБ: `tools/ci/fetch_rates.py`.

**Скрипты**
- `fetch_wikidata.py` (`--country CC`). Название за границей: русская метка, иначе местная латиницей или
  кириллицей, иначе английская; язык пишется в `nameLang`. **Машинного перевода нет.**
- `inflect.py` — падежи.
- `fetch_extras.py`.
- `bars_from_extract.py`, `food_from_extract.py`.
- `parks_from_extract.py` — именованные `leisure=park|garden` от 3 000 м², не частные.
- `build_catalogue.py` — чистая функция от сырых файлов; лимиты на город по населению.
- `build_parks.py` — 5–60 парков на город, `townsSha256`.
- `countries.py` — 9 стран. Абхазия выделена из Грузии.
- `write_lock.py` — lock-файлы с подсчётами и sha256.

**Workflows**
- `data.yml` — полный российский конвейер, около 4 ч → `bot/data-N`, `bot/raw-N`.
- `data-osm.yml` — только бары и еда (около 40 мин, скачивает 3.7 ГБ) → `bot/data-osm-N`, `bot/raw-osm-N`.
  Запускается изменением `data-osm.request`.
- `data-abroad.yml` — по стране на задание, не больше 2 параллельно, лимит 340 мин на задание.
  - Задание `ru-parks` качает выгрузку России в 8 потоков с проверкой md5.
  - Задание `publish` пушит **ветки без истории** (orphan) `bot/data-abroad-N` и `bot/raw-abroad-N`: токен CI не
    может пушить историю с изменениями workflow-файлов.
  - Управляется файлом `data-abroad.request`: `countries: … | none`, `ru-parks: yes|no`, `from-run: <run id>`
    (переопубликовать артефакты старого прогона без новой загрузки).
- `data-extras.yml`, `data-photos.yml`.

**Как забрать результат:**
```
git fetch origin bot/<name>:refs/remotes/origin/bot/<name>
git checkout origin/bot/<name> -- <пути>
python3 backend/planner/tools/gen_api_contracts.py
make check
```

**Лицензии.** Каталог как целое — **производная база данных OSM по ODbL 1.0**.
- Wikidata — CC0. Выдержки Wikipedia/Wikivoyage — CC BY-SA 4.0. Фото — лицензия каждого файла; только-GFDL
  исключены.
- Текст лицензии: `data/catalogue/README.md`, `LICENSE-ODbL.txt`; в приложении — «О данных».
- Импорт OSM в курируемую базу заморожен до ответа юриста (D-IR-08, LEG-01).

**Известный долг.** Российские бары, еда и POI теряют OSM-объекты-«области» (`a…`). Исправлено только для парков
и заграницы; российский путь оставлен нетронутым ради стабильности сырых данных.

## 18. Известные ограничения и долги

**Данные — демо**
- **Отели, придорожные кафе, АЗС и площадки на трассе вымышлены** (в интерфейсе — «демо»). Цены жилья и еды — по
  умолчанию от населения.
- Обед в прогулке — оценка 600 ₽.
- Цены платных дорог не проверены (`verified: false`).

**Маршруты.** Вне ручного графа — оценочные (`approxDistances`). Реальные дороги будут только с GraphHopper на
сервере; на тестовой ВМ он выключен.

**Заграница**
- Все факты (топливо, сборы, документы, переходы) — «не проверено».
- Ожидание на границе неизвестно, в план заложен запас 120 мин.
- Ночёвки и еда без цены; топливо считается с курсом ЦБ только при наличии файла курсов на сервере.
- Нет дорожного графа; координаты переходов примерные.
- Нет сёл и курортов.
- В Абхазии 3 города; Южная Осетия внутри Грузии.
- Часовые пояса: Абхазия — Москва по выбору; Казахстан — расхождение Wikidata и tzdata.
- Английские названия в Армении и Грузии.

**Качество планов.** «Весело» на М-11 даёт мало остановок (мало данных). Нет правила «закат».

**Сервер.** Один поток движка на процесс; лимиты можно обойти регистрацией новых устройств. Нет переноса в РФ
(152-ФЗ).

**Не сделано по плану**
- Админка Directus, курируемая база мест (300 проверенных мест к M3).
- Лендинг не опубликован.
- Интервью: 0 из 30–50.
- Юрлицо и юрист по ODbL.
- Ключ подписи Яндекса.

**Процесс**
- Всё после 27.10 не в `main`; релиз `verst-latest` старый.
- `docs/install-ceo.md` описывает старую демо-схему и ссылку `verst-latest`.
