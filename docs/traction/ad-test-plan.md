## 1. Цель и решение по итогам теста

**Вопрос.** Какое из трёх обещаний приводит людей в лист ожидания (Telegram-канал, D-IR-05)
дешевле всего и на какой площадке?

**Чем закончится тест.** Цена за подписку (CPL) по каждому варианту и каждой площадке,
конверсия лендинга и вариант-победитель. Если разница не значима, пишем «явного победителя
нет». Результат записывается в `docs/traction/` (критерий приёмки VAL-02).

**Чего тест не покажет.** Установки и удержание: приложение ещё не выпущено. Спрос на платную
версию: это BIZ-06. Точный CAC для unit-экономики: по CPL видно только порядок величины.

## 2. Гипотезы по вариантам

Лендинг один, вариант задаётся параметром `?v=a|b|c` (Web Designer, `web/landing/index.html`).
Меняется только обещание: заголовок, подзаголовок, акценты. Всё остальное на странице
одинаковое.

| Вариант | Обещание (заголовок лендинга) | Гипотеза | Кому прежде всего | Что будет, если вариант выиграет |
| --- | --- | --- | --- | --- |
| **a** | «Маршрут с ночёвками под ваш темп за 10 секунд» | Главная боль в том, что разбить многодневную поездку на дни и найти ночёвку долго и сложно. Обещание скорости и ночёвок «под ваш темп» даст самую дешёвую подписку | Семьи и пары, которые едут на 2–4 дня | Главный экран и стор-листинг строятся вокруг ночёвок и темпа |
| **b** | «Честная стоимость поездки: каждая строка с формулой» | Главная боль в том, что непонятно, сколько стоит поездка. Обещание прозрачной сметы даст самую дешёвую подписку | Те, кто держит семейный бюджет | Наверх выходит путевой лист со стоимостью. Поисковые страницы «сколько стоит поездка из Москвы в X» (ENG-06) получают приоритет |
| **c** | «С детьми и собакой: только места, где вам рады» | Самая острая боль у тех, кто едет с детьми и собакой. Узкое обещание даст меньше кликов, но более высокую конверсию в подписку | Семьи с детьми и собакой | Проверка мест (DATA-02) становится ядром продукта и маркетинга |

**Ограничение варианта c [Legal].** На октябрь 2026 у нас 0 проверенных мест
(`.claude/product-marketing.md`). Поэтому в рекламе обещание подаётся как будущее
(«готовим запуск», «скоро»). Это правило и для вариантов a и b: продукт ещё не вышел,
у демо-сборки вымышленные отели (там же). Каждый текст до запуска проверяет Legal (§12, п. 6).

вариант (§3).

| Настройка | Значение |

| Ключевые фразы (таргетинг по поисковым фразам) | Те же группы, что для Директа (§4.2), без группы «Направления» (в VK она слишком узкая) |
| Сужение | Интересы ∪ ключевые фразы. Сегменты не пересекаем, иначе аудитория выйдет слишком маленькой |
| Исключения | Подписчики нашего Telegram-канала не исключаются: у VK нет такого сегмента. Это учтено в сверке (§8) |
| Look-alike, ретаргетинг | Не используем: у нас нет базы, а сравнение должно идти на холодной аудитории |

Найденный источник пишет, что алгоритм VK переопределяет ручные настройки таргетинга
[§15 [V4]]. Поэтому одинаковые настройки во всех трёх кампаниях здесь обязательны.

## 8. Основная метрика: цена подписки на лист ожидания

### 8.1 Определения

Окно W: D1 00:00 – D14 23:59 МСК. Для подписок берём W′ = W + 24 ч (до D15 23:59): человек
кликает в последний день и подписывается чуть позже. Базовый органический уровень вычитается
за то же окно W′.

Для каждой ячейки k:

| Обозначение | Что это | Откуда |
| --- | --- | --- |
| S_k | Расход с НДС = расход в кабинете без НДС × 1,22 | Отчёт кабинета за W |
| I_k, K_k | Показы и клики | Отчёт кабинета за W |
| V_k | Визиты лендинга с `utm_source` и `utm_content` ячейки | Метрика за W |
| C_k | Визиты с достигнутой целью `tg_click` | Метрика за W |
| J_k | Подписки на канал, отнесённые к ячейке | §8.2 или §8.3 |

| Метрика | Формула |
| --- | --- |
| CTR | K_k / I_k |
| CPC | S_k / K_k |
| Конверсия лендинга в намерение | CR_tg = C_k / V_k |
| Цена клика в Telegram (вторичная) | CPL_tg = S_k / C_k |
| Доля дошедших до подписки | JR = J_k / C_k |
| **Основная: цена подписки** | **CPL_join = S_k / J_k** |

Для варианта суммируются числители и знаменатели обеих ячеек, например
CPL_join(a) = (S_yandex-a + S_vk-a) / (J_yandex-a + J_vk-a). Средние ячеек не усредняются.
Результат по каждой площадке приводится **отдельно**, сумма его не подменяет.

### 8.2 Способ A (рекомендуемый): своя ссылка-приглашение на каждую ячейку

Сам Telegram не знает, откуда пришёл подписчик. Зато администратор канала может создать
несколько **именованных ссылок-приглашений** (имя до 32 знаков), и для каждой ссылки видно,
сколько людей вступило по ней [факт: §15 [TG1], [TG2]]. Через Bot API это видно
поштучно: в обновлении о вступлении есть поле `invite_link` — ссылка, по которой вступил
человек [факт: §15 [TG3]].

1. CEO создаёт канал и ссылки (в приложении: профиль канала → Изменить → Пригласительные
   ссылки):
   - `val02-yandex-a`, `val02-yandex-b`, `val02-yandex-c`, `val02-vk-a`, `val02-vk-b`,
     `val02-vk-c`;
   - `site-organic`: лендинг без UTM или с неизвестным источником;
   - `interview`: ссылка, которую дают на интервью (`interview-kit.md` это разрешает);
   - `team`: друзья и команда.
2. Лендинг выбирает ссылку по паре `utm_source` + вариант. **Нужно изменение у Web
   Designer:** вместо одного `TELEGRAM_URL` словарь `TELEGRAM_URLS` с ключами
   `yandex-a` … `vk-c` и запасным вариантом `TELEGRAM_URL` → `site-organic`. Запрос идёт
   через Manager.
3. J_k = число вступивших по ссылке ячейки k. Значения снимаются в D0 (должно быть 0) и в
   D15 23:59. Счётчики сразу записываются в отчёт, с датой и временем снятия.

**Ограничения способа A:**

- ссылку можно переслать, тогда вступивший по пересланной ссылке засчитается ячейке;
- кто кликнул, но потом нашёл канал поиском, по ссылке не засчитается, и J_k получится
  заниженным;
- кто уже подписан, повторно не считается;
- отписки по ссылкам не видны;
- можно ли сделать дополнительные ссылки у **публичного** канала, проверяется на канале до
  запуска (минут 5). Если нельзя, делаем канал приватным на время теста или переходим к
  способу B.

### 8.3 Способ B (запасной): сверка одной общей ссылки

Используется, если словарь ссылок на лендинге не сделан.

1. **База.** За 7 дней до D1 CEO каждый день в 10:00 МСК записывает число подписчиков N(t).
   Органический прирост за сутки: b = (N(D1) − N(D1 − 7)) / 7.
2. **Окно.** N_start = N на D1 00:00, N_end = N на D15 23:59. Если в статистике канала есть
   графики новых подписчиков и отписок (они доступны не всем каналам; порог по размеру
   канала в найденных источниках не подтверждён, §15 [TG4]), берём валовые вступления
   G и отписки L. Если нет, используем чистый прирост и пишем об этом.
3. **Прирост от рекламы:**
   J_inc = G − b × 15 − J_known, а без статистики J_inc = (N_end − N_start) − b × 15 − J_known.
   Здесь J_known — известные вступления не из рекламы (интервью, команда, посты CEO), а
   15 — число суток в W′.
4. **Распределение по ячейкам:** J_k = J_inc × C_k / ΣC.
5. **Проверки.** Если J_inc > ΣC, вступлений больше, чем кликов; это ошибка учёта или
   органика, и вывод не делается. Если J_inc < 0, рекламного эффекта не видно.

**Ограничения способа B (честно):**

- шаг 4 предполагает, что доля дошедших до подписки одинакова во всех ячейках. Поэтому
  по способу B варианты **по сути сравниваются по CPL_tg**, а J только масштабирует
  результат. Различие вариантов в том, кто именно подписывается после клика, этот способ не
  видит;
- `tg_click` теряется у части посетителей (блокировщики, уход со страницы раньше отправки
  цели), так что C занижено;
- органика «шумит», а при малых числах её разброс сопоставим с эффектом рекламы;
- любые посты о канале в других местах во время теста смешивают данные. **Правило:** с D−7
  по D15 канал нигде больше не продвигается, а все известные вступления записываются в
  J_known.

### 8.4 Качество подписчиков

На D15 и D22 записываем число подписчиков. Отписки за 7 дней после теста показывают,
насколько аудитория случайная. По ячейкам это видно только по способу A, если подключён
бот (§8.2). Без бота — только в целом по каналу.

## 9. Как выбрать победителя [решение]

Всё считает скрипт по выгрузкам из кабинетов и Метрики (`tracking-plan.md` §4).

1. Проверяем минимум данных (§7). Если он не набран, пишем «данных недостаточно».
2. Ранжируем варианты по CPL_join (по способу B — по CPL_tg).
3. **Значимость.** Конверсию лендинга CR_tg (и JR по способу A) сравниваем χ²-тестом по трём
   вариантам при α = 0,05. Если он значим, лидера попарно сравниваем с двумя остальными
   z-тестом для долей при α = 0,025 (поправка Бонферрони на 2 сравнения).
4. **Победитель:** вариант с наименьшим CPL_join, у которого преимущество в конверсии
   значимо по шагу 3 и который не хуже остальных ни на одной площадке. Если на Директе и в VK
   выиграли разные варианты, пишем обоих по площадкам, без общего победителя.
5. Если значимости нет, пишем: «явного победителя нет; лидер по CPL — X (направление, не
   вывод)». Решение тогда принимается вместе с интервью VAL-01.
6. Итог записывается в недельный файл `docs/traction/` с цифрами, окнами и источниками.
