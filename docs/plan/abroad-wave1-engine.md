# Поездки за рубеж, волна 1: движок (решение CEO 29.10)

Сервер планирует поездки из России в Беларусь, Казахстан, Грузию, Абхазию, Армению, Узбекистан, Киргизию и Турцию. В Азербайджан поездку не строит: граница закрыта для легковых до 02.01.2027. Телефон ничего из этого не получает. В APK нет каталогов `abroad/`, мир `russia_v1` на телефоне не изменился.

Данные — из [abroad-wave1-data.md](abroad-wave1-data.md) (каталоги стран) и [abroad-wave1-sources.md](abroad-wave1-sources.md) (цены, сборы, правила, переходы). Все факты второго документа прочитаны из поисковой выдачи, страницы первоисточников не открывались. Поэтому всё, что движок говорит о загранице, помечено «не проверено».

## Как устроено

**Мир `world_v1` (только сервер).** Это `russia_v1` и каталоги стран, найденные на диске:
- путь — `VERST_ABROAD_DIR`, по умолчанию `backend/planner/abroad/<cc>/catalogue_*.json.gz`;
- если папки нет или она пустая, мир — только Россия, а точка за рубежом получает понятную ошибку;
- `abroad.lock`, если он есть, сверяется по sha256: недокопированный деплой падает при старте.

Код лежит в `verst_planner/foreign/` (имя `abroad` внутри пакета запрещено тестом APK). Загрузка: `mobile.load_abroad(path, rates_path)`, на телефоне её никто не вызывает.

**Поездка внутри России — байт в байт прежняя.** `AbroadPlanner` смотрит на точки поездки. Если все они в России, план, оценку, замену остановки и пересчёт цены делает прежний русский планировщик. Проверено тестами:
- одинаковые JSON `russia_v1` и `world_v1` для трёх поездок и готового маршрута;
- голдены не изменились;
- контрактные тесты API сравнивают ответ сервера с `russia_v1` телефона.

**Изменения в общем движке.** Они не срабатывают, пока у мира нет `BorderPort`, а такой порт есть только у `world_v1`:
- новые хуки `Planner` (сейчас пустые);
- `Ports.borders`;
- вид остановки `border`;
- предупреждение `ABROAD`;
- поля `stop.border` и `trip.abroad` — пишутся только если они есть;
- `InvalidInput.country / message_ru / until`.

## Что работает

1. **Проверка точки.** Если в 60 км от точки есть город каталога (радиус `insideRussia` приложения), страна точки — страна ближайшего города: Россия или загруженная страна. Если города в 60 км нет, действует прежнее правило: внутри старого прямоугольника России (`in_russia`, он покрывает и Крым) точка — Россия и строится как раньше (Телецкое озеро, точка в Охотском море даёт прежний `UNREACHABLE`). Решение координатора 29.10: никакой регрессии для России.
   - Вне прямоугольника и без города в 60 км → `INVALID_INPUT`, `reason: outside_supported`, без страны, с русским сообщением.
   - Страна загружена, но правил для неё нет → то же с `country`.
   - Азербайджан → `reason: border_closed`, `country: "AZ"`, `until: "2027-01-02T06:00:00+04:00"`, `messageRu` «Граница закрыта для легковых до 2 января 2027: …». После этой даты по часам планировщика граница считается открытой (тест).
2. **Маршрут.** Дорожного графа за рубежом нет.
   - Русские участки (подряд идущие точки в России) идут через прежнюю маршрутизацию: на сервере GraphHopper, в тестах модель дорог.
   - Участок, у которого хотя бы один конец за рубежом, считается откалиброванной моделью дорог (прямая × коэффициент).
   - В поездке `approxDistances: true`.
   - Платные дороги считаются только на русских участках, прежним портом.
3. **Пограничные переходы** (`resources/border_crossings.json`). Между точками разных стран движок ищет путь через переходы:

   | Направление | Переход |
   |---|---|
   | РФ — Грузия | Верхний Ларс |
   | РФ — Армения | Ларс, затем Садахло |
   | РФ — Турция | Ларс, затем Сарпи |
   | РФ — Абхазия | Псоу |
   | Абхазия — Грузия | только через Россию: Псоу и Ларс |
   | РФ — Казахстан | граница с Казахстаном |
   | РФ — Узбекистан, РФ — Киргизия | через Казахстан |
   | РФ — Беларусь | граница-отметка |

   В каждом месте перехода встаёт остановка `kind: "border"`. Её поле `border` содержит:
   - откуда и куда;
   - факты о переходе с источниками;
   - сезонный риск (Ларс: ноябрь — март) с признаком, попадает ли дата поездки;
   - документы, сборы и правила страны въезда с URL и типом источника;
   - `unverified: true`.

   **Ожидание.** Ни один источник не называет время ожидания для Ларса и Казахстана. Поэтому строка «Время ожидания неизвестно» и запас `border.buffer_min` из `planner_config.json` (сейчас 120 мин). Он подписан: «это настройка планировщика, а не факт». Для Псоу показано то, что пишут водители (вторичный источник), а запас тот же. Граница с Беларусью — отметка без остановки: 0 мин.

   **Координаты.** Ни в источниках, ни в каталогах координат переходов нет. Поэтому `coordsApprox: true`, а в `coordsNoteRu` сказано, откуда точка:
   - Ларс → Владикавказ (ближайший город каталога; Ларс в Северной Осетии по источнику);
   - Псоу → Адлер, если он есть в каталоге, иначе Сочи;
   - Сарпи → Батуми (источник: «у Батуми»);
   - Казахстан, Садахло и остальные → место, где прямая линия маршрута пересекает границу, у ближайшего города каталога этой стороны. Для Казахстана в остановке перечислены Бугристое, Сагарчин и Караузек как самые загруженные; сказано, что Сырым закрыт для легковых до конца 2026.
4. **Остановки за рубежом.** Достопримечательности, еда и города ночёвок берутся из каталогов стран тем же конвейером. Российские фильтры не ослаблены. Остановка берётся только на участке своей страны: российского парка после границы и армянского музея у грузинской дороги не будет. Особенности за рубежом:
   - нет выдуманных гостиниц и кафе;
   - нет билетов «по умолчанию»: цена билета неизвестна (прежний механизм E-2);
   - нет часов «по умолчанию»: показываются только часы из OSM;
   - крепость подписана «Крепость», а не «Кремль».
5. **Часовые пояса.** Регионы стран берутся из каталогов вместе с поясами. По правилу блока 1 остановки в другом поясе показывают местное время. Пример: «По местному времени — 19:07 (+1 ч)» после Ларса.
6. **Деньги.** Рублёвый итог (`cost`) считается прежним алгоритмом, но без того, у чего за рубежом нет рублёвой цены.
   - **Ночёвки и еда за рубежом** — цены неизвестны. У остановки `costRub: 0`, `unknownFacts: ["price"]`, строка «Цена за границей неизвестна — в рублёвый итог не входит». У ночёвки без гостиницы причина «гостиниц там в наших данных нет».
   - **Топливо за рубежом** — цена страны в местной валюте из `resources/abroad_rules.json`, с датой, URL и типом источника. Если цен две (две сети, два города), берётся верхняя.
     - Строка топлива в рублях появляется только при курсе Банка России (`VERST_RATES_FILE`, файл `tools/ci/fetch_rates.py`). Подпись строки: «Грузия: <регион>».
     - Без курса топливо остаётся в местной валюте.
     - Без цены — «не учтено». Так для Абхазии (надёжного источника нет), Армении (только данные GlobalPetrolPrices с некоммерческой лицензией) и АИ-92 в Турции.
   - **Сборы и страховки.** Сумма входит в «учтённые суммы» (`localTotals`), только если выполнены все условия:
     - сбор обязательный;
     - сумма из официального или первичного источника;
     - другой источник ей не противоречит.

     Иначе сбор показан с причиной: «вторичный источник», «источники расходятся», «суммы нет», «не обязателен». Это правило §12 документа источников. Пример учтённого сбора: дорожный сбор Армении 10 000 AMD / 15 дней (kdmid.ru). Пример неучтённого: TPL Грузии 30 GEL — цена со вторичного сайта.
   - **Платные дороги за рубежом.** Беларусь: 0 для машин из ЕАЭС (BelToll, официальный источник). Остальные страны: «не учтено» с текстом из источников (Казахстан, Турция HGS, тоннели Киргизии).
   - **`abroad.roubleTotalIncomplete: true`** и список `notInRoubleTotalRu` — что именно не вошло в рублёвый итог. К `cost.totalNoteRu` добавляется «За границей посчитано не всё — смотрите блок «За границей»». Строка сохраняется после замены остановки и пересчёта цены.
7. **Предупреждение `ABROAD`** (уровень info): цены и правила за границей не проверены.

## Что приблизительно

- **Расстояния и время на зарубежных участках** — модель дорог, а не дороги. Горные участки (Ларс — Тбилиси) в реальности медленнее.
- **Точка перехода** — город каталога или пересечение прямой с границей, а не сам пункт пропуска.
- **Страна точки у границы** — по ближайшему городу каталога. Если город по ту сторону ближе, точка отнесётся к соседней стране.
- **Километры по странам в `abroad.countries[].km`** — по ближайшему городу вдоль линии. Так же делится строка топлива. Первые 10–60 км после перехода могут уйти в российский регион.
- **Выбор остановок** — по стране участка, а не по точной границе.

## Что неизвестно (и движок так и говорит)

- Время ожидания на всех переходах, кроме слов водителей о Псоу.
- Цены гостиниц и еды за рубежом.
- Цены топлива в Абхазии и Армении, АИ-92 в Турции, АИ-95 в Азербайджане.
- Тарифы платных дорог Казахстана, Турции (KGM) и Азербайджана; проходит ли маршрут по тоннелям Киргизии.
- Цена страховок на границе: Казахстан, Турция, Киргизия; медстраховка Грузии.
- Курсы UZS, KGS, AZN: в `fetch_rates.py` их нет, поэтому эти суммы только в местной валюте.
- Координаты всех переходов.

## Формат ответа (дополнения, только у поездок за рубеж)

- `trip.abroad`:
  - `unverified`, `checkedAt`, `noteRu`;
  - `countries[]`:
    - `code`, `nameRu`, `currency`, `km`, `tz`;
    - `fuel` {`fuelType`, `litres`, `pricePerLitre`, `priceRange`, `validFrom`, `amount`, `rub`, `inRoubleTotal`, `sources`, `noteRu`};
    - `tolls`, `fees[]`, `nightsUnpriced`, `mealsUnpriced`, `documents`, `rules`;
  - `localTotals[]`, `rates`, `ratesNoteRu`;
  - `roubleTotalIncomplete`, `notInRoubleTotalRu[]`, `totalNoteRu`.
- Остановка `kind: "border"` (`sign: "city"`, не заменяемая):
  - поле `border`: `crossingId`, `from`, `to`, `fromRu`, `toRu`, `marker`;
  - точка: `coordsApprox`, `coordsNoteRu`;
  - ожидание: `waitKnown`, `waitRu`, `waitSources`, `bufferMin`, `bufferRu`;
  - `facts`, `risks[]` (с `appliesOnTripDate`), `documents`, `fees`, `rules`, `unverified`.
- Предупреждение `{"code": "ABROAD", "level": "info"}`.
- Ошибки: `INVALID_INPUT` с `reason` `outside_supported`, `border_closed`, `no_crossing` или `ready_route_abroad`. Мост добавляет `country`, `messageRu`, `until`, когда они есть. API кладёт `country` и `until` в `details`, а `messageRu` — в `message`.

## Развёртывание

1. Слить ветку `bot/data-abroad-<N>`: `backend/planner/abroad/<cc>/…` и `abroad.lock`.
2. Образ. `infra/api/Dockerfile` копирует `backend/planner/abroad` в `/srv/verst/planner/abroad`, `Dockerfile.dockerignore` пропускает папку. В git папка лежит с одним `.gitkeep`, поэтому `COPY` не падает и без данных. Тогда сервер планирует только по России и отвечает как раньше: Тбилиси внутри старого прямоугольника получает прежний `UNREACHABLE`, точка вне прямоугольника — `outside_supported`.
3. Переменные (в `infra/api/.env.example`):
   - `VERST_ABROAD_DIR` — путь к каталогам. По умолчанию копия в образе.
   - `VERST_RATES_FILE` — курсы Банка России в формате `tools/ci/fetch_rates.py`. Например, cron на хосте раз в день: `python3 tools/ci/fetch_rates.py /srv/verst/rates/rates.json` и монтирование только для чтения. Без файла деньги за рубежом остаются в местной валюте.
4. Проверка после старта:
   - в логе `engine ready` поле `abroad` перечисляет страны;
   - `POST /v1/trips/plan` Москва → Тбилиси даёт `approxDistances` и остановку `border`;
   - Москва → Баку даёт 400 `border_closed`.
5. Память и время старта растут на размер каталогов: ожидается 1–4 МБ сжатых на все страны (оценка из документа данных). Мир `world_v1` делит объекты мест с `russia_v1`, заново строятся только индексы.

## Что изменилось на сервере для поездок по России

Ничего. `WORLD` в `backend/api/verst_api/engine.py` теперь `world_v1`, но поездка, все точки которой в России, идёт в прежний русский планировщик. Точка без города каталога в 60 км внутри старого прямоугольника России считается Россией, как раньше. Тесты API про такую точку (Охотское море, `UNREACHABLE`) не менялись.

## Что менять в Android

Приложение сейчас само блокирует назначение за рубежом:
- `VerstFlow.destinationAbroad` (`Destination.abroad` по коду страны Nominatim);
- плашка в `NavigatorScreen`;
- `go()` и `estimateTarget()` ничего не отправляют.

Нужно:

1. **Пускать назначение за рубежом на сервер.** Условие: включено «Планировать на сервере» (`AppPrefs.planOnServer`, `serverConsent`) и есть сеть. Тогда `destinationAbroad` не блокирует ПОЕХАЛИ и оценку, а запрос идёт через `ServerPlannerGateway`.
   - Офлайн или без сервера оставить плашку, но с другим текстом: «за границу планирует только сервер — нужен интернет и включённое планирование на сервере».
   - Оценку (`estimate`) для такого назначения пока не запрашивать на телефоне: сервер её не отдаёт отдельным методом.
2. **Не откатываться на телефон при ответе сервера для поездки за рубеж.** Сейчас `ServerClient.FINAL = {UNREACHABLE, TOO_SHORT}`, и на любую другую ошибку `ServerPlannerGateway` пересчитывает план на телефоне. Тогда `border_closed` превращается в бессмысленный план или `outside_russia`. Добавить в окончательные ошибки `INVALID_INPUT` с причинами `outside_supported`, `border_closed`, `no_crossing` и показать `error.message` как есть. В нём русский текст, например «Граница закрыта для легковых до 2 января 2027: …».
3. **Вид остановки `border`.** DTO принимают `kind` строкой и игнорируют неизвестные ключи, поэтому поездка разберётся и без правок. Но строку нужно нарисовать:
   - имя «Граница: Верхний Ларс — Дарьяли» и время;
   - лист с `border.documents`, `fees`, `facts`, `risks` и источниками (ссылки);
   - «Время ожидания неизвестно» и запас `bufferRu`;
   - пометку «не проверено» и `coordsNoteRu`.
   Остановка не заменяемая, у отметки Беларуси `dwellMin = 0`. В передаче маршрута в навигатор (`handoff`) её нет: координаты приблизительные.
4. **Блок «За границей» в смете** из `trip.abroad`:
   - по странам: км, топливо в валюте и в ₽, если есть курс;
   - сборы: учтённые и показанные;
   - платные дороги;
   - сколько ночёвок и приёмов пищи без цены;
   - `notInRoubleTotalRu`;
   - пометка «не проверено».

   Итог в рублях подписать как неполный (`roubleTotalIncomplete`). Строку `cost.totalNoteRu` движок уже дополняет.
5. **`unknownFacts: ["price"]`** у ночёвок и еды за рубежом — новое значение. Показать `unknownRu`.
6. **Пересчёт сметы на телефоне** (`CostCalculator`, патч состава) для поездки с `abroad` лучше отдавать серверу. Единицы стоимости за рубежом урезаны, а строку «За границей…» локальный пересчёт не добавит. Если пересчитывать на телефоне, нужно сохранить `abroad` и дописывать `abroad.totalNoteRu` к примечанию.
7. **Текст «поделиться»** берёт итог в рублях как есть. Для поездки с `abroad` стоит добавить «без расходов за границей». Это правка и в Kotlin `ShareTextBuilder`, и в `explain/share.py`; пока не сделано, чтобы не трогать контракты share-text.

## Открытые вопросы

1. **Решено (координатор 29.10): без регрессии для России.** Точка без города каталога в 60 км внутри старого прямоугольника — Россия, как раньше. Следствие: без каталога страны её точка дальше 60 км от российских городов (Тбилиси без данных Грузии) получает прежний `UNREACHABLE`, а не `outside_supported`. Точнее станет только с контурами стран (OSM admin_level=2) в конвейере данных.
