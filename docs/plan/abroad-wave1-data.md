# Поездки за рубеж, волна 1: данные (решение CEO 29.10)

Каталоги мест для поездок в Беларусь, Казахстан, Грузию, Абхазию, Армению, Азербайджан, Узбекистан, Киргизию и Турцию. Эти поездки строит только сервер, поэтому каталоги в APK не попадают. Плюс парки для российского каталога: отдельным файлом `catalogue_parks.json.gz`, который можно выпустить независимо.

Сами данные в песочнице не собрать: Wikidata, Geofabrik и OSM из неё недоступны. Их собирает CI (`.github/workflows/data-abroad.yml`). В этой ветке лежат скрипты, таблицы, workflow и тесты; файлов каталогов пока нет.

## Что сделано

**Скрипты получили ключ страны.** У `fetch_wikidata.py`, `fetch_extras.py` и `build_catalogue.py` появился `--country CC`. Страны описаны в `backend/planner/tools/data/countries.py`. Без ключа всё работает как раньше, для России:
- запросы к Wikidata остались прежними символ в символ (тест `test_abroad_data.QueriesTest`);
- российская сборка из опубликованных сырых веток (`bot/raw-7`, `bot/extras-1`, `bot/photos-1`, `bot/raw-osm-2`) совпала с файлами в `verst_planner/resources/` байт в байт. Проверено по рецепту из `data/catalogue/README.md` 29.10.2026 для `wd-20261029-osm2`, до правок и после них.

**Названия.** Сначала русская метка Wikidata. Если её нет, то метка на местном языке, но только для латиницы или кириллицы (be, kk, ky, uz, az, tr, ab). Иначе английская. Машинного перевода нет. Для объектов OSM порядок такой: `name:ru`, потом `name` на латинице или кириллице, потом `name:en`. В каждой строке есть колонка `nameLang` (ru / be / en / local …). Падежи pymorphy3 строятся только для русских названий.

**Регионы.** Это первый уровень деления страны: коды ISO 3166-2 из P300 (`BY-HM`, `GE-TB`, `TR-34` …). Если город попадает в два региона с кодом, берётся меньший код.

**Часовые пояса** записаны в таблице `tools/data/region_tz_abroad.tsv`. Источник — база IANA tzdata 2026e (`zone1970.tab`), а не память. На этапе `country` CI сверяет их с Wikidata P421 и пишет результат в `catalogue_meta.tzCheck`.

| --- | --- | --- |
| BY | Europe/Minsk | +3 |
| TR | Europe/Istanbul | +3 |

**Абхазия.** В Wikidata её места бывают записаны под P17 «Грузия», под P17 «Абхазия» или под обоими. Каталоги `GE` и `AB` запрашивают оба значения P17. Город попадает в `AB`, если его регион `GE-AB` или среди его P17 есть Q23334. Остальные города идут в `GE`. Регион `AB` подписан как «Абхазия», валюта — RUB, выгрузка OSM — грузинская выгрузка Geofabrik.

**Классы достопримечательностей.** Для зарубежья добавлены мечеть (вид `church`), мавзолей (`monument`), медресе и археологический памятник (`attraction`). Идентификаторы проверяет шаг `classes` по английским меткам; если id неверный, класс ищется заново по русской метке.

**OSM.** Выгрузку Geofabrik для страны находит `geofabrik_url.py` по коду ISO в официальном индексе Geofabrik, путь не угадывается. Из выгрузки берутся бары, еда, парки, OSM-места и платные парковки. Сумма платной парковки в рублях (`rph`) за рубежом не вычисляется: «1 р/ч» в Минске — это белорусские рубли. Исходный текст тарифа сохраняется в `meta.parking.charge`.

**Парки** (`parks_from_extract.py`, `build_parks.py`):
- что берётся: `leisure=park|garden`, только площади, с названием, не частные, от 3 000 м²;
- что хранится: площадь в м² и центр, взвешенный по площади;
- город: ближайший город каталога;
- одна строка на название;
- лимит на город: 5–60 в зависимости от населения, крупные парки первыми;
- `poi`: ссылка на ту же точку в `catalogue_pois`, если она там есть.

У файла парков свои поля `version`, `townsSha256` и `licence`. Для России его собирает задача `ru-parks` в `data-abroad.yml` по уже выпущенному каталогу. `data.yml` после полной пересборки тоже пересобирает парки, потому что меняется порядок городов.

**APK.** Каталоги лежат в `backend/planner/abroad/<cc>/`, вне пакета `verst_planner`. Gradle-задача `stagePlannerSources` берёт только `verst_planner/**`. Шаг `diagnose.py apk` в `android.yml` теперь проваливает сборку, если в APK есть путь с `abroad/`, включая архивы Chaquopy внутри APK. Это проверяют тесты.

## Как запустить

1. В ветке `ccr-*` отредактировать `backend/planner/tools/data/data-abroad.request` и запушить. Сам файл новый, поэтому первый пуш этой ветки тоже запустит прогон. Необязательные строки в файле:
   - `countries: GE AB` — по умолчанию все девять стран;
   - `ru-parks: no` — по умолчанию `yes`.
2. Когда workflow будет в `main`: Actions → data-abroad → Run workflow, или `gh workflow run data-abroad.yml --ref main -f countries="GE AB"`.
3. Результат:
   - ветка `bot/data-abroad-<N>`: `backend/planner/abroad/<cc>/catalogue_{meta,towns,pois,bars,food,parks}.json.gz`, `abroad/abroad.lock` (размеры, sha256, счётчики, проверки), российские `catalogue_parks.json.gz` и `catalogue_parks.lock`, отчёты `tools/data/report-abroad/`;
   - ветка `bot/raw-abroad-<N>`: сырые ответы по странам (`raw/raw-<cc>.tar.gz`, части OSM под ODbL 1.0).

   Пересборка из сырых данных: `tar -xzf raw-ge.tar.gz -C raw/ge`, затем `python3 tools/data/build_catalogue.py raw/ge --country GE --version … --built-at …` и `build_parks.py raw/ge OUT --country GE`. Версия и дата берутся из `abroad.lock`. Нужна база часовых поясов (`zoneinfo`).
4. Задачи по странам идут не больше двух одновременно. У каждой один клиент Wikidata: 1 запрос в секунду, User-Agent из `http_util.py`. Overpass не используется. Геопоиск Commons ограничен 1 500 местами на страну. Лимит одной задачи — 340 минут.

## Прогон 1 (run 40966628193) и исправления

- **Парки: 0 во всех выгрузках** (RU, BY, GE). `osmium export --add-unique-id=type_id` пишет многоугольник парка с id `a<id площади>` (2 × id линии, 2 × id отношения + 1), а `w…` у замкнутой линии — это её LineString без площади. Теперь `parks_from_extract.osm_object` переводит `a…` обратно в линию или отношение. Тест на выгрузке в форме osmium: `tests/data/samples/abroad_ge/parks.geojsonseq`. Парки больше не валят каталог страны.
- **Города: 504 и 429 на WDQS** (KZ, UZ, KG, AZ, AB). Один запрос (547 классов × P17 × путь P131* к региону) не укладывался в 60 с. За рубежом запрос теперь разбит:
  - города запрашиваются частями по 60 классов, без пути к региону;
  - регионы запрашиваются отдельно, пачками по 150 городов;
  - упавшая часть делится пополам.
  Одновременно идут не больше двух задач. Запрос для России не изменился.
- **Тот же `a…` в старом конвейере.** Из-за него и бары, еда, OSM-места российского каталога теряют объекты-отношения и площадные `a…` (`elements_from_features` принимает только `n/w/r`). Я это не менял: иначе изменились бы российские сырые данные. Это отдельная задача.

## Ожидаемые размеры (оценка, не измерение)

Российский каталог: 1 114 городов, 1,50 МБ, примерно 1,35 КБ на город. Число городов за рубежом станет известно после первого прогона. При 800–2 500 городах на все девять стран выйдет примерно 1–4 МБ на сервере. Российские парки добавят примерно 0,2–0,4 МБ к APK: до 60 парков на город, обычно 5. `test_size_budget` (цель 2,5 МБ) пока считает только `FILES`, без парков.

## Чего нет

- Данных: ждём первый прогон CI.
- Описаний на английском, если нет русской статьи Википедии или листинга Викигида. Сейчас берутся только ru-источники.
- Фильтра иностранных сетей: список брендов только российский.
- Разбора платных парковок в местной валюте.
- Оценки наследия ЮНЕСКО: уровень наследия считается по русским ярлыкам «федерального/регионального значения». За рубежом это даёт 0,3, и качество мест ниже. Менять общую формулу без пересборки России нельзя.
- Сёл и посёлков: за рубежом берутся только подклассы «city or town». Туристические посёлки вроде грузинских даба (Степанцминда) и курортов могут не попасть в каталог.

## Что нужно движку (следующая задача, логику планирования я не трогал)

- **Пути.** `backend/planner/abroad/<cc>/` (`by kz ge ab am az uz kg tr`) — это не ресурсы пакета, `resources.read_bytes` их не видит. Нужен загрузчик по пути, например из переменной окружения. Тест `test_packaging.test_no_file_reads_outside_helper` разрешает чтение файлов только в `resources/__init__.py`, `cli.py` и фейковом мире.
- **Сервер.** В `infra/api/Dockerfile` и `Dockerfile.dockerignore` добавить `backend/planner/abroad` после слияния bot-ветки. `COPY` несуществующей папки ломает сборку образа, поэтому сейчас это не сделано.
- **Формат.** Тот же: `verst_planner.catalogue.from_docs` читает файлы как есть, это проверено тестом. Отличия от российского:
  - лишняя колонка `nameLang` (в towns, pois, bars, food, parks);
  - `meta.country` {code, wikidata, nameRu, currency, labelLangs};
  - `meta.tzCheck`;
  - пустой `meta.links`;
  - `gen` и `prep` = null у нерусских названий;
  - `meta.parking.rph` = null и `charge` с текстом, если валюта не рубль;
  - `licence.copy` и `scope` указывают на `abroad/`.
- **Регионы и пояса.** Они в `meta.regions` (code, nameRu, tz), коды ISO 3166-2 своей страны; у Абхазии `GE-AB`. Российская `region_tz.tsv` за рубежом не нужна.
- **Валюты:** BY BYN, KZ KZT, GE GEL, AB RUB, AM AMD, AZ AZN, UZ UZS, KG KGS, TR TRY. Курсы ЦБ в приложении (`tools/ci/fetch_rates.py`) есть для KZT, BYN, TRY, GEL, AMD. Нет AZN, UZS, KGS.
- **Виды мест.** За рубежом крепость и замок тоже получают вид `kremlin`, а подпись «Кремль» там неверна; нужна «Крепость». Мечеть получает вид `church` («Храм»).
- **Парки.** Перед использованием файла проверять `townsSha256` против загруженного `catalogue_towns`. `poi` помогает не показать парк дважды. Файл не входит в `FILES` и `load_packaged`.
- **Остальное.** Проверка `in_russia`, топливо, платные дороги и миры — у движка. Абхазия и Грузия — разные каталоги: граница по Ингуру и Псоу.

## Открытые вопросы

1. **Где лежат каталоги.** В задаче был пример `verst_planner/resources/abroad/`. Каталоги лежат в `backend/planner/abroad/`, потому что `android/**` трогать нельзя, а Gradle пакует весь `verst_planner/**`. Так APK не может их взять. Устраивает?
2. **Казахстан.** По tzdata 2026e с 1 марта 2024 года вся страна живёт по UTC+5, у неё один пояс, а не два. Таблица записана так.
3. **Время в Абхазии.** Взято Europe/Moscow (фактически используемое время). В IANA своего пояса у Абхазии нет, её относят к GE (Asia/Tbilisi, +4). tzCheck покажет, что записано в Wikidata P421.
4. **Южная Осетия.** Её города с P17 «Грузия» попадут в каталог `GE`, а проехать к ним можно только из России. Выделить её, как Абхазию?
5. **Посёлки и курорты.** Добавлять ли классы посёлков и курортов (Степанцминда, Гудаури) после отчёта первого прогона?
6. **Описания.** Нужны ли английские выдержки Википедии там, где нет русских?
