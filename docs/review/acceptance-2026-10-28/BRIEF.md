план поездки по дням с остановками (достопримечательности, еда, ночёвки, заправки), сметой (бензин, платные
дороги, жильё, еда, билеты) и передачей маршрута в навигатор. Ядро планировщика — Python, работает прямо на
телефоне (Chaquopy) по открытым данным (OSM, Wikidata); с 27.10 план можно строить и на тестовом сервере.
Режим «По городу»: пешие прогулки по городу с пресетами (обзорная, музеи, с собакой, бары).

Стадия: MVP на тестовых данных («мок-сборка»), ещё не опубликовано. Каталог мест реальный (Центральная Россия
+ Поволжье), цены отелей и часть мест — демонстрационные. Аудитория первых тестов — друзья и семья CEO.

## Что можно запускать здесь

- Тесты движка: `cd backend/planner && python3 -m unittest discover` (535 тестов, ~70 с), `make check` в корне (ruff, mypy, тесты).
- Движок руками: `python3 -c "import sys; sys.path.insert(0,'backend/planner'); from verst_planner import mobile; ..."` — см. `backend/planner/verst_planner/mobile.py` (`load_world`, `plan`, `city_route`, …) и `docs/contracts/v2/*.json` как примеры запросов/ответов.
- CLI планировщика: `backend/planner/verst_planner/cli.py`.
- Тесты API: `cd backend/api && python3 -m pytest` (нужен PostgreSQL; если не поднимается — опишите, что хотели проверить).
- Android-сборку и Gradle здесь запустить нельзя (нет Android SDK); приложение оценивается по скриншотам, коду и строкам интерфейса.
- Интернет из песочницы ограничен: GitHub доступен, большинство других сайтов — нет.

## Структура отчёта

1. **Вердикт** в одном абзаце: принимаете ли вы решение в своей роли и при каких условиях.
2. **Оценка по шкале 1–10** с одной фразой обоснования.
3. **Что сделано хорошо** — 3–7 пунктов.
4. **Замечания**, отсортированные по важности: критичные / важные / мелкие. У каждого: что не так, где (доказательство), чем грозит, что предлагаете.
5. **Чего не удалось проверить** и как это проверить CEO вручную.
6. **Три шага, которые вы сделали бы первыми**.
