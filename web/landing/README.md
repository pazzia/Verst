# Лендинг Версты (VAL-02)

Одна статическая страница с листом ожидания для рекламного теста трёх обещаний. HTML, CSS и немного
JavaScript, без фреймворков и внешних библиотек. Ничего не опубликовано: домен и хостинг выбирает
CEO (D-IR-04).

```
web/landing/
├── index.html        страница: конфиг в начале, стили и скрипт внутри
├── fonts/            Verst Sans Narrow 400/600/700 и Verst Hand (WOFF2, OFL) + лицензии и NOTICE
├── screenshots/      скриншоты 360 и 1280 px по каждому варианту + фокус и форма
└── tools/            скрипты скриншотов и проверок (публиковать не нужно)
```

Публикуются только `index.html` и папка `fonts/`.

## Как посмотреть локально

```bash
cd web/landing
python3 -m http.server 8765
# открыть http://127.0.0.1:8765/?v=a  (или ?v=b, ?v=c)
```

Без настроенного `TELEGRAM_URL` вверху висит красная плашка «Страница не настроена». Так задумано:
сломанную страницу не получится опубликовать незаметно. Для просмотра можно временно вписать любую
ссылку `https://t.me/...`.

## Блок конфигурации

Он в самом начале `index.html` (`window.VERST_CONFIG`). Больше ничего править не нужно.

| Ключ | Что это | Кто заполняет | Если пусто |
| --- | --- | --- | --- |
| `TELEGRAM_URLS` | Словарь ссылок-приглашений по ячейкам теста: `yandex-a`, `yandex-b`, `yandex-c`, `vk-a`, `vk-b`, `vk-c` | CEO создаёт ссылки, Growth Marketer проверяет | Посетитель ячейки получает запасную ссылку, в консоли браузера предупреждение |
| `TELEGRAM_URL` | Запасная ссылка `site-organic`: без UTM, другой источник, пустая ячейка | CEO | Кнопки не работают, на странице красная плашка |
| `METRIKA_ID` | Номер счётчика Яндекс Метрики, только цифры | CEO (D-IR-06) | Метрика не загружается совсем, ни одного запроса к Яндексу |
| `FORM_ENABLED` | Включить подписку по e-mail | Только после одобрения Legal | `false`: формы нет, вместо неё текст «откроем скоро» |
| `FORM_ENDPOINT` | `https://` адрес, принимающий POST с JSON | Разработчик / CEO | Форма не включится |
| `PRIVACY_URL` | Ссылка на утверждённую политику обработки персональных данных | Legal | В подвале видна пометка «ЮРИСТ: …», форма не включится |
| `CONSENT_VERSION` | Версия утверждённого текста согласия, уходит с каждой заявкой | Legal | Форма не включится |
| `CONTACT` | E-mail или ссылка `https://` для связи | CEO | В подвале видна пометка «CEO: …» |

Ссылки на Telegram принимаются только в виде `https://t.me/...` (подходят и `https://t.me/+код`,
и `https://t.me/имя_канала`). Всё остальное считается пустым значением.

## Варианты обещания

Вариант задаётся параметром `?v=`. Без параметра или при неверном значении показывается **a**.
Вариант выставляется до отрисовки, поэтому мигания нет. Меняются только заголовок, подзаголовок и
картинка первого экрана, остальная страница одинакова.

| `?v=` | Заголовок | Картинка первого экрана |
| --- | --- | --- |
| `a` | Маршрут с ночёвками под ваш темп — за 10 секунд | Экран навигатора: Москва → Казань по дням, ночёвка в Нижнем Новгороде и причина выбора |
| `b` | Честная стоимость поездки: у каждой строки — формула | Путевой лист: шесть статей с формулами и итог ≈ 23 000 ₽ (цифры условные, так и подписано) |
| `c` | С детьми и собакой — только туда, где вам рады | Зеркало заднего вида с экипажем и список того, что учитывается для детей и собаки |

Рекламные ссылки (шаблон из `docs/traction/ad-test-plan.md` §5.5 и `tracking-plan.md` §1.5):

```
https://<домен>/?v=a&utm_source=yandex&utm_medium=cpc&utm_campaign=val02-promise-2026-11&utm_content=a
https://<домен>/?v=b&utm_source=yandex&utm_medium=cpc&utm_campaign=val02-promise-2026-11&utm_content=b
https://<домен>/?v=c&utm_source=yandex&utm_medium=cpc&utm_campaign=val02-promise-2026-11&utm_content=c
https://<домен>/?v=a&utm_source=vk&utm_medium=cpc&utm_campaign=val02-promise-2026-11&utm_content=a
https://<домен>/?v=b&utm_source=vk&utm_medium=cpc&utm_campaign=val02-promise-2026-11&utm_content=b
https://<домен>/?v=c&utm_source=vk&utm_medium=cpc&utm_campaign=val02-promise-2026-11&utm_content=c
```

## Ссылки Telegram по ячейкам (изменение по плану теста)

Так сделано по `ad-test-plan.md` §8.2 (способ A): каждая ячейка получает свою
ссылку-приглашение, и подписки считаются по ячейкам.

- **Ячейка** = `utm_source` после белого списка + **показанный** вариант, например `yandex-b`.
  При `?v=x&utm_source=yandex` показан вариант a, значит ячейка `yandex-a`.
- Если ссылка для ячейки есть в `TELEGRAM_URLS`, обе кнопки Telegram ведут на неё.
- Во всех остальных случаях кнопки ведут на `TELEGRAM_URL` (`site-organic`): нет UTM, источник
  `telegram`, `interview` или `community`, неизвестный источник, пустая ссылка у ячейки.
  Для интервью и команды в плане свои ссылки, их раздают напрямую, а не через лендинг.
- Как проверить (`tracking-plan.md` §1.7, проверка 4): откройте рекламную ссылку ячейки и посмотрите
  консоль браузера. Там будет строка `Telegram: ячейка yandex-b → cell yandex-b https://t.me/+…`. Тот же
  итог записан в атрибут `<html data-tg-link="cell yandex-b">`. Потом нажмите кнопку и убедитесь, что
  Telegram открыл ссылку с нужным именем (`val02-yandex-b`).
- Имена ссылок в Telegram только служебные (`val02-vk-a`), без имён людей (`tracking-plan.md` §1.6).

## События (Яндекс Метрика)

Метрика загружается, только если задан `METRIKA_ID`. Инициализация:
`clickmap: true, trackLinks: true, accurateTrackBounce: true, webvisor: false`. Вебвизор выключен,
пока Legal не решит иначе. В Метрике нужно создать JS-цели с такими идентификаторами
(`tracking-plan.md` §1.2):

| Цель | Когда | Параметры |
| --- | --- | --- |
| `page_view` | Один раз за загрузку, после выбора варианта | `variant`, `utm_source`, `utm_campaign`, `utm_content` |
| `tg_click` | Нажатие любой кнопки Telegram | `variant`, `utm_source`, `cta_location` = `hero` \| `final` |
| `faq_open` | Раскрытие вопроса | `variant`, `utm_source`, `faq_id` = `q1`…`q4` (текст вопроса не передаётся) |
| `form_submit` | Только при включённой форме, после ответа сервера 2xx | `variant`, `utm_source`, `form` = `email_waitlist` |

- `cta_click` не используется: на странице нет кнопок призыва, которые не ведут сразу в Telegram.
  Если такие появятся (например, липкая кнопка с прокруткой к подписке), цель добавим.
- `utm_source` проходит белый список: `yandex`, `vk`, `telegram`, `interview`, `community`.
  Без метки уходит `none`, любое другое значение уходит как `other`. Даже если в ссылку попадёт
  e-mail, в Метрику он не уйдёт. `utm_campaign` и `utm_content` проверяются регуляркой
  `^[a-z0-9]+(-[a-z0-9]+)*$`, всё остальное уходит как `other`.
- `variant` — это показанный вариант, а не запрошенный.
- `tg_click` уходит до перехода. Переход идёт в колбэке Метрики или через 300 мс, если колбэк не
  пришёл (например, у посетителя блокировщик). Ctrl/Cmd/Shift-клик открывает новую вкладку как
  обычно, цель при этом тоже отправляется.
- Персональных данных нет ни в одной цели и ни в одном параметре. E-mail из формы уходит только на
  `FORM_ENDPOINT`, в Метрику идёт лишь факт отправки.
- Для отладки страница пишет все цели в `window.verstEvents`, даже без Метрики.

## Подписка по e-mail

**Решение:** пока форма выключена, её **нет на странице**: ни полей, ни неактивной кнопки. Вместо неё
написано: «Подписку по e-mail откроем скоро — сначала опубликуем политику обработки персональных
данных». Неактивная форма выглядит сломанной и отвлекает от основной кнопки, а отправить через неё
всё равно ничего нельзя. HTML формы при этом есть в коде (атрибут `hidden`), так что включение — это
только правка конфига.

Форма включится, только когда выполнены **все** условия: `FORM_ENABLED: true`, `FORM_ENDPOINT` с
`https://`, `PRIVACY_URL` и `CONSENT_VERSION`. Если чего-то не хватает, форма остаётся скрытой, а
в консоли появляется ошибка.

Во включённой форме одно поле e-mail и галочка согласия. Галочка изначально не отмечена и
обязательна. Её текст сейчас временный и помечен «ЮРИСТ: заменить». Ошибки показываются у поля, и
фокус переходит на первую из них. Есть скрытое поле-ловушка для ботов и тайм-аут 10 с. После
отправки появляется подтверждение. Скриншоты: `screenshots/form-enabled-error-360.png`,
`screenshots/form-enabled-success-360.png`.

Что уходит на `FORM_ENDPOINT` (POST, `Content-Type: application/json`):

```json
{"email": "…", "consent": true, "consent_version": "2026-11-01", "variant": "b", "utm_source": "yandex"}
```

Требования к приёмнику: ответ 2xx при успехе, CORS для домена лендинга, серверы в России
(152-ФЗ), хранение времени и версии согласия вместе с адресом.

## Шрифты

Шрифты те же, что в приложении, и подключены с сайта, без Google Fonts и чужих CDN. Verst Sans
Narrow — это переименованный IBM Plex Sans Condensed (design/decisions.md DES-100). Verst Hand —
это Marck Script, переименованный из-за Reserved Font Name. Оба шрифта урезаны до латиницы,
кириллицы и типографских знаков и лежат в WOFF2, всего 66 КБ. Лицензии OFL и NOTICE лежат в `fonts/`.
Если шрифт не загрузится, текст покажется системным узким шрифтом (`font-display: swap`).

## Проверки (как проверялось)

```bash
cd web/landing && python3 -m http.server 8765 &
npm i --no-save --prefix /tmp/verst-tools playwright axe-core@4.10.2   # один раз
NODE_PATH=/tmp/verst-tools/node_modules node tools/verify.js            # проверки, итог «ALL PASS»
NODE_PATH=/tmp/verst-tools/node_modules node tools/shots.js             # скриншоты в screenshots/
```

Результат последнего прогона: **ALL PASS** (48 проверок).

- **Нет горизонтальной прокрутки на 320, 360 и 1280 px** во всех трёх вариантах:
  `scrollWidth` = ширине окна, ни один элемент не выходит за край.
- **axe-core 4.10** (wcag2a/aa, wcag21aa, wcag22aa, best-practice): 0 нарушений во всех вариантах на
  360 и 1280 px, с раскрытыми вопросами. Включённую форму проверяли отдельно, тоже 0.
- **Контраст** посчитан по формуле WCAG для каждой пары цветов. Текст: от 5,1:1 (подпись на
  путевом листе) до 16,7:1, основной текст 16,7:1. Белый на синем знаке 7,1:1, тёмный на жёлтой
  кнопке 12,7:1. Граница поля ввода 4,95:1, жёлтое кольцо фокуса 11,8–12,7:1 (требование 1.4.11 —
  3:1). Жёлтый текст стоит только на тёмном фоне.
- **Фокус:** проход по Tab на 360 px. У каждого элемента видна жёлтая рамка 3 px с отступом 3 px,
  и элемент в видимой области (2.4.7, 2.4.11). Скриншоты: `screenshots/focus-*.png`.
- **prefers-reduced-motion:** единственная анимация (разметка дороги) выключается.
- **Вес:** 53 КБ без шрифтов (цель < 300 КБ), 66 КБ шрифтов, 5 запросов. Сторонних запросов нет,
  пока не задан `METRIKA_ID`.
- **HTML:** html-validate 8.24, 0 ошибок.
- **Ячейки Telegram и цели:** 8 сценариев (`yandex-b`, `vk-a`, пустая `vk-c`, `Test User`, e-mail
  в `utm_source`, `interview`, без меток, неверный `?v=`). Для каждого проверены нужная ссылка и
  параметры всех целей в очереди Метрики, и что `@`/`mail` в очередь не попадают.

Скриншоты лежат в `screenshots/`: `{a,b,c}-{360,1280}-fold.png` (первый экран) и `-full.png`
(страница целиком). Для съёмки в страницу подставлялась тестовая ссылка `https://t.me/verst_preview`.

## Что сделать до публикации

1. **Домен и хостинг** выбирает CEO (D-IR-04). Хостинг с HTTPS, лучше в России. Отдавать
   `fonts/*.woff2` с `Cache-Control: max-age=31536000, immutable`.
2. **Telegram-канал** и восемь ссылок-приглашений (`val02-yandex-a` … `val02-vk-c`, `site-organic`,
   `interview`, `team`) создаёт CEO. Шесть ссылок ячеек вписать в `TELEGRAM_URLS`, `site-organic` —
   в `TELEGRAM_URL`. Проверить, что у канала можно сделать дополнительные ссылки (§8.2).
3. **Метрика:** создать счётчик, вписать `METRIKA_ID`, создать цели `page_view`, `tg_click`,
   `faq_open`, `form_submit`, подключить счётчик к Директу. Пройти чек-лист `tracking-plan.md` §1.7.
4. **Legal:** политика обработки персональных данных → `PRIVACY_URL`. Нужно ли уведомление о cookie
   для Метрики? Текст и версия согласия для формы. Только после этого `FORM_ENABLED: true`.
5. **Контакты** → `CONTACT` (CEO). После шагов 4–5 в подвале не должно остаться жёлтых пунктирных
   пометок «ЮРИСТ/CEO».
6. **Маркировка рекламы (38-ФЗ)** делается в объявлениях и у площадок (ERID), а не на этой странице.
   Лендинг — посадочная страница, а не рекламный материал с пометкой «Реклама».
7. Перед запуском убрать `<meta name="robots" content="noindex">`, если страница должна попасть в
   поиск. На время теста трёх вариантов с одного адреса мы рекомендуем `noindex` оставить.
8. Обещание «за 10 секунд» (вариант a) должно быть подтверждено (см. вопросы ниже).

## Ограничения

- Без JavaScript кнопки Telegram не работают: ссылка берётся из конфига. Таких посетителей из
  рекламы почти нет, а вторая точка правки ссылок нам не нужна.
- Картинки первого экрана — это вёрстка, а не скриншоты приложения. Это иллюстрации, и подписи
  «пример», «цифры условные» стоят прямо на них.

## CRO-самопроверка

**Контекст.** Холодный платный трафик из Директа и VK, одно обещание на ячейку, одно действие —
подписка на Telegram-канал. Цель теста — сравнить обещания, а не вырастить конверсию любой ценой,
поэтому всё, кроме первого экрана, во всех вариантах одинаковое.

**Что уже сделано (быстрые победы):**

- Совпадение с объявлением: заголовок на знаке повторяет обещание из объявления (`ad-test-plan.md`
  §5), вариант приходит из той же ссылки.
- Одна главная кнопка: жёлтая, с понятным результатом («Следить за запуском в Telegram»). На 360 и
  1280 px она видна без прокрутки. Повторяется в конце страницы. Навигации, которая уводит со
  страницы, нет.
- Снятие трения прямо под кнопкой: что будет в канале, «бесплатное, без регистрации», «отписаться
  можно в любой момент». Подписка не требует ни телефона, ни e-mail.
- Возражения закрыты вопросами: цена, iPhone, регионы, данные. Плюс блок «Мы на старте» — честный
  статус вместо социального доказательства, которого у нас пока нет.
- Честность как довод: «проверенных мест пока нет», «цифры условные», «оценка, а не счёт». Для
  аудитории, уставшей от выдуманных AI-маршрутов, это работает на доверие и защищает от жалоб на
  недостоверную рекламу.
- Скорость: 53 КБ без шрифтов, один HTML, без сторонних скриптов до включения Метрики.
- Измеримость: `page_view` и `tg_click` по ячейкам, `faq_open` показывает, какие возражения
  волнуют, ссылки Telegram дают подписки по ячейкам.

**Идеи тестов на потом** (не в этом тесте, чтобы не смешивать с обещанием):

1. Липкая кнопка Telegram внизу на мобильных после первого экрана (добавит `cta_location=sticky`).
   Гипотеза: +CTR в Telegram на длинной мобильной странице.
2. Текст кнопки: «Следить за запуском в Telegram» против «Позвать меня в тест». Второй конкретнее
   про выгоду, но обещает больше.
3. Ссылка в Telegram в новой вкладке против перехода в той же: что даёт меньше потерь цели и
   больше вступлений.
4. Реальный скриншот приложения на первом экране вместо вёрстки — когда в сборке будут настоящие
   данные (не раньше ENG-03).
5. Форма e-mail рядом с кнопкой Telegram, когда Legal её одобрит. Гипотеза: охват людей без
   Telegram против размывания главного действия.
6. Короткий блок «Чем Верста отличается» сразу под первым экраном — для холодного трафика из VK.
